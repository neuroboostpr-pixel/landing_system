# 📘 База знаний: Миграция промптов на GPT-5


## 🚨 QUICK START (Emergency Reference)


### Ваш промпт сломался? 30-секундная диагностика:
```
1. Есть ли слова "можешь", "пожалуйста", "если не сложно"? → УБРАТЬ
2. Есть ли "будь кратким, но подробным"? → ИСПРАВИТЬ противоречие  
3. Есть ли четкая цель в первом предложении? → ДОБАВИТЬ
4. Указан ли формат ответа? → ДОБАВИТЬ


Если 2+ проблемы → читайте раздел "Экстренная миграция"
```


### Decision Tree: Куда идти?
```
┌─ У меня промпт работает плохо
│  ├─ Есть противоречия → "Устранение противоречий" 
│  ├─ Слишком вежливо → "Русские команды"
│  └─ Нет структуры → "Быстрые шаблоны"
│
├─ Хочу мигрировать с GPT-4
│  ├─ Агентная задача → "Агентная миграция"
│  ├─ Код → "Кодинг миграция" 
│  └─ Анализ → "Анализ миграция"
│
└─ Настраиваю LLM агента
   ├─ Нужна автоматика → "JSON схемы"
   └─ Нужна валидация → "Автопроверки"
```

# 🎯 Русские команды vs вежливые просьбы


## Проблема русского промптинга
GPT-5 лучше понимает четкие команды, чем вежливые просьбы.


## Таблица замен:
| ❌ Вежливая просьба | ✅ Четкая команда |
|---------------------|-------------------|
| Не мог бы ты помочь | Выполни задачу |
| Пожалуйста, проанализируй | Проанализируй |
| Если можешь, найди | Найди |
| Было бы хорошо если | Сделай |
| Попробуй сделать | Сделай |
| Постарайся найти | Найди минимум [N] |


## Системное правило:
**Если промпт звучит как письмо бабушке — переписывай командами.**

# ⚙️ Устранение противоречий


## Топ-5 русских противоречий:


### 1. "Кратко, но подробно"
```
❌ Было: "Дай краткий, но подробный анализ"
✅ Стало: "Дай краткий вывод (2-3 предложения) + детальное обоснование"
```


### 2. "Всегда, если"  
```
❌ Было: "Всегда проверяй источники, если они доступны"
✅ Стало: "Проверяй источники A, B, C. Если недоступны — сообщи"
```


### 3. "Только, но можно"
```
❌ Было: "Используй только стандартные библиотеки, но можешь внешние если проще"
✅ Стало: "Используй только стандартные библиотеки Python"
```


### 4. "Точно, примерно"
```
❌ Было: "Дай точные данные, приблизительные тоже подойдут"  
✅ Стало: "Точные данные обязательны. При отсутствии — сообщи"
```


### 5. "Быстро, качественно"
```
❌ Было: "Сделай быстро и качественно"
✅ Стало: "Приоритет: качество результата. Время: не критично"
```

# ✅ Автопроверки


## Python validation script:
```python
import re


def validate_prompt_quick(text):
    """Быстрая проверка промпта для LLM агента"""
    issues = []
    
    # Проверка вежливости
    politeness = ["пожалуйста", "не мог бы", "если можешь"]
    for word in politeness:
        if word in text.lower():
            issues.append(f"politeness:{word}")
    
    # Проверка противоречий  
    contradictions = [
        (r"кратк\w*.*подробн", "краткий+подробный"),
        (r"всегда.*если", "всегда+если"),
        (r"только.*можно", "только+можно")
    ]
    
    for pattern, issue in contradictions:
        if re.search(pattern, text, re.IGNORECASE):
            issues.append(f"contradiction:{issue}")
    
    # Проверка структуры
    has_goal = any(word in text.lower() for word in ["цель:", "задача:", "выполни"])
    if not has_goal:
        issues.append("missing:goal")
        
    return {
        "issues": issues,
        "score": max(0, 10 - len(issues) * 2),
        "status": "good" if len(issues) <= 1 else "needs_fix"
    }
```

# 📊 Success metrics


## KPIs для миграции:
- **Quality improvement**: +15% task success rate
- **Efficiency**: response time не хуже baseline  
- **Consistency**: 95% стабильность результатов
- **User satisfaction**: не ниже 8/10


## Измерение success rate:
```python
def measure_success(old_results, new_results):
    """Сравнение эффективности до/после миграции"""
    old_success = sum(1 for r in old_results if r['success']) / len(old_results)
    new_success = sum(1 for r in new_results if r['success']) / len(new_results)
    
    improvement = (new_success - old_success) / old_success * 100
    
    return {
        "old_rate": old_success,
        "new_rate": new_success, 
        "improvement": f"{improvement:.1f}%",
        "migration_success": improvement >= 10
    }
```

# 🚨 Cursor findings: "Будь тщательным" вредит GPT-5


## ❌ Критическая проблема старых промптов
**Cursor обнаружили:** фразы типа "be THOROUGH" заставляют GPT-5 делать избыточные поиски и tool calls.


## Русские фразы-вредители:
```
❌ УБРАТЬ НЕМЕДЛЕННО:
- "Будь тщательным в анализе"
- "Постарайся найти как можно больше информации"  
- "Проверь все возможные источники"
- "Изучи вопрос досконально"
- "Не пропусти ни одной детали"
```


## ✅ Правильные замены:
```
Вместо: "Будь тщательным в анализе" 
Замена: "Найди 3-5 ключевых проблем и остановись"


Вместо: "Постарайся найти больше информации"
Замена: "Максимум 3 запроса к базе данных"


Вместо: "Проверь все возможные источники"  
Замена: "Проверь источники A, B, C"
```


## Почему это критично:
GPT-5 **naturally introspective** — он уже склонен к глубокому анализу. Фразы "будь тщательным" создают **over-searching** и замедляют работу.

# 📋 FailSafeQA: Работа с документами


## Проблема: промпты плохо работают с реальными документами
Документы содержат шум, опечатки, неполную информацию.


## ✅ Behavioral Priorities (проверенный паттерн):
```
Приоритеты поведения (по порядку):
1) Grounding: Используй ТОЛЬКО текст из [Документ]. Никакой внешней информации.
2) Проверка фактов: Убедись что ответ явно присутствует в тексте.
3) Устойчивость: Игнорируй опечатки и неточности в вопросе.
4) Обработка OCR: Игнорируй артефакты сканирования, восстанавливай смысл.
```


## Шаблон для работы с документами:
```
Проанализируй документ. Цель: [конкретная цель].


Правила работы:
- Используй ТОЛЬКО информацию из предоставленного документа
- Каждый факт подтверждай цитатой из текста
- Игнорируй опечатки и сканерные артефакты
- Если информации недостаточно — сообщи что именно нужно


Формат ответа:
РЕЗУЛЬТАТ: [ответ]
ИСТОЧНИК: "[точная цитата из документа]"


Если ответить нельзя:
РЕЗУЛЬТАТ: Недостаточно информации в документе
НУЖНО: [что именно требуется для ответа]
```

# 🗣️ Tool preambles: Объяснения для пользователя


## Проблема: пользователь не понимает что делает агент


## ✅ Tool preambles = краткие объяснения перед действиями


### Шаблон tool preamble:
```
Перед использованием инструмента объясни:
- Что сейчас будешь делать
- Зачем это нужно для решения задачи  
- Какой примерно результат ожидается


Формат: "Сейчас [действие] для [цель]. Ожидаю найти [результат]."
```


### Примеры на русском:


**Для поиска в базе данных:**
```
"Сейчас ищу данные о продажах за последний квартал для анализа трендов. 
Ожидаю найти помесячную статистику."


[выполнение поиска]
```


**Для анализа документа:**  
```
"Сейчас анализирую финансовый отчет для выявления ключевых показателей.
Ожидаю найти данные о выручке, прибыли и основных расходах."


[анализ документа]
```


**Для создания кода:**
```
"Сейчас пишу функцию для обработки CSV данных согласно техническим требованиям.
Ожидаю создать готовую функцию с примером использования."


[написание кода]
```


### Добавить в агентные промпты:
```
Коммуникация с пользователем:
- Перед каждым действием кратко объясни что делаешь и зачем
- После действия сообщи что получил
- В конце дай краткое резюме всей работы


Формат объяснений: "Сейчас [действие] → [результат] → [следующий шаг]"
```
