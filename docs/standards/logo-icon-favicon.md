# Logo / Icon / Favicon — обязательный флоу (B3, ✅ отработан)

**Источник:** спека [2026-06-12-reference-driven-flow-spec.md](../superpowers/specs/2026-06-12-reference-driven-flow-spec.md) §3.3 (T17/T18/T19, T42).

## Логотипы брендов

- **Векторизация исходника, не генерация.** Логотип — узнаваемый знак, его
  нельзя «нарисовать похожим». Берём файл у клиента (PNG/JPG/SVG) и трассируем
  в SVG (`vtracer`). Codex image_gen для логотипов **запрещён** (даёт похожую
  выдумку). Codex — только для абстрактных иконок/инфографики без бренд-знаков.
- **Подключение — inline SVG с `currentColor`** (цвет управляется
  дизайн-системой). НЕ `mask-image` на локальный файл (не виден при открытии
  файла напрямую).
- **Нормализация SVG:** viewBox оставить, width/height убрать,
  `fill="currentColor"`.

## Ровный оптический размер набора

Несколько SVG рядом нельзя ставить одинаковой высотой в px — у них разная
«масса чернил». Размер нормируется по **площади закрашенных пикселей**
(замер рендером), не по высоте/ширине. Алгоритм с формулами — консолидированная
спека 2026-06-03, правило SVG, шаг 9.

## Favicon

- Если логотип — широкая надпись, favicon делается из **монограммы** (первые
  буквы фирменным шрифтом и цветом), а не из сжатого логотипа (нечитаем в 16px).
- Генерация: headless Chrome (рендер HTML с монограммой) + обрезка.
- Подключение: `<link rel="icon">` (+ apple-touch-icon) в теме; на WordPress —
  site icon через `wp_options`, не атрибут блока (см. asset-pipeline.md).
- Деплой favicon — обязательный шаг /landing-deploy (зона C4).
