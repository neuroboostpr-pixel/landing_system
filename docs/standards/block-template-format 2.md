# Стандарт формата шаблона блока (B35)

Канон для `block-library/<folder>/<id>/assets/template.html`. Переопределяет
любые «по умолчанию» решения агентов и генераторов.

## 1. Фрагмент, не документ

Шаблон — это **фрагмент** секции, а НЕ полный HTML-документ.

- ✅ `<style>…</style>` + один корневой `<section class="lp-…">…</section>`
- ❌ `<!DOCTYPE html>`, `<html>`, `<head>`, `<body>`

Причина: compose конкатенирует фрагменты блоков в одну страницу. Полный
документ ломает сборку.

## 2. Плейсхолдеры — только `{{slot:name}}`

Весь редактируемый контент — через текстовые плейсхолдеры `{{slot:name}}`.

- ✅ `<h2 class="lp-x__title">{{slot:title}}</h2>`
- ❌ `data-slot="title"` атрибуты (legacy ru-* формат)
- ❌ `[HEADLINE: …]`, `[Вопрос 1]` — русский текст-подсказка в скобках
- ❌ захардкоженный осмысленный текст («Оставьте заявку») вне `{{slot}}`

Причина: `{{slot:name}}` язык-нейтрален. Текст внутри `[скобок]` или
`data-slot`-элемента «протекает» в превью и мешает мультиязычности.

Технические строки (label кнопки-иконки, `aria-label` без перевода) допустимы
как обычный текст, если это не пользовательский контент.

## 3. Имена слотов синхронны с meta.yaml

Каждое имя в `{{slot:name}}` обязано присутствовать в `meta.yaml::slots[].name`
(кроме item-схемы — `item-N-field`, `card-N-title` и т.п., которые
обрабатываются по regex в inject-content). И наоборот: meta не должна объявлять
слоты, которых нет в шаблоне.

## 4. CSS — inline, префикс `lp-`

- Стили внутри `<style>` в начале фрагмента.
- Классы с префиксом `lp-<block>` чтобы не конфликтовать между блоками.
- Только токены/нейтральные значения; без внешних `<link>`.

## 5. Мобильный вариант (опционально)

`assets/template-mobile.html` — тот же контракт (фрагмент, `{{slot}}`), если
блоку нужна отдельная мобильная вёрстка.
