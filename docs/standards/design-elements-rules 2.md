# Design Elements Rules — как агент добавляет визуальные элементы

**Статус:** обязательный стандарт этапа 07c (создание макета).
**Источник:** спека [2026-06-12-reference-driven-flow-spec.md](../superpowers/specs/2026-06-12-reference-driven-flow-spec.md), разделы 3.1, 3.4.
**Применяет:** block-composer.

## Базовый принцип (универсальный)

**Элемент добавляется под конкретную потребность места, а не «для красоты».**
Каждый дизайн-элемент отвечает на вопрос «какую проблему этого места он решает?»:

- блок плоский (текст без визуальной опоры) → иконка/цифра;
- в блоке зияет пустая зона → декор или визуал-объект;
- переход между секциями голый → разделитель;
- фото лежит «в боксе встык» → вырезать и дать глубину.

Если на вопрос «зачем здесь этот элемент» ответа нет — **элемент не нужен**.

**Плотность:** не более ~1 акцентного декор-объекта на смысловую зону. Перебор
декора = «шумно» — хуже, чем пусто.

**Премиальность** даёт композиционная глубина (слои, вырезанные фото за рамкой,
крупные цифры-якоря, формы-подложки, разделители-формы). Премиум **НЕ даёт**:
тёмный фон сам по себе, обилие анимаций, много эффектов.

## Декор агент генерирует САМ (B1)

Каждую фигуру/блоб/волну агент рисует под конкретный дизайн — CSS
(`border-radius` для блобов) или inline SVG. Готового банка форм нет:
- `block-library/_shapes/` (18 фигур) — **только подсказка-палитра** («какие
  вообще бывают формы»). Итоговую форму генерировать под проект, не вставлять
  файл как есть.
- Хранилища «разобранных референсов-эталонов» нет и не будет — работаем только
  с референсом конкретного клиента + правилами этого стандарта.

## Каталог элементов *(справочно, не чек-лист)*

| Элемент | Как делается | Куда ставится | Запрет |
|---|---|---|---|
| **Иконка** | inline-SVG под стиль системы либо Lucide; `currentColor`=токен; в плашке, единый оптический размер | плоские блоки с одним текстом (списки преимуществ, сегменты, пункты) | эмодзи вместо иконок |
| **Цифра-якорь** | display-шрифт, крупно, акцентный цвет | только реальные числа из контента (проценты, годы, цены, сроки) | порядковые 01–04 у списка услуг; «водяная» цифра-призрак за текстом |
| **Декор-знак** (росчерк, звезда, стрелка) | inline-SVG, `currentColor` | пустоты блока: над заголовком, углы цветных зон, у CTA | заметный — по согласованию |
| **Подчёркивание-росчерк** | inline-SVG `<path>` со `stroke`, чуть неровный | под **1** ключевым словом заголовка | не под каждым словом |
| **Форма-кромка / разделитель** | трассировка из референса (vtracer) либо CSS/SVG; `currentColor`; `<symbol>`/`<use>` | между секциями разного фона | см. «Разделители» |
| **Форма-подложка** (блоб, овал) | CSS `border-radius` (неровные значения) или SVG | под вырезанным фото человека; под иконкой в карточке | — |
| **Фото человека / бренд-объект** | реальный файл клиента → rembg → PNG → на подложку | hero (с наездом за край); блок-портрет | **лицо не генерировать** |
| **Логотип бренда** | векторизация исходника (vtracer); normalize; inline-`<svg>` | где нужен знак; несколько рядом — нормировать по площади чернил | **не генерировать**; не `mask-image` |
| **Абстрактный визуал** (маскот, инфографика) | генерация на хромакее `#FF00FF` → rembg → под палитру | крупные пустые зоны | без бренд-знаков и реальных лиц |

## Алгоритм добавления элемента *(справочно)*

1. **Анализ блока** — рендер-скриншот: где пусто, где плоско, где голый переход.
2. **Потребность словами**: «здесь не хватает иконок» / «правая зона пустая».
3. **Подобрать элемент** по каталогу под потребность.
4. **Источник** — по дереву решений ниже.
5. **Согласовать** заметный декор с пользователем («блок → место → элемент»);
   мелкие иконки — без согласования.
6. **Создать.** `currentColor`=токен. Выровнять по границам контента.
7. **Проверить рендером** — не сливается, не на лице/тексте, не перекрывает.
8. **Сверить**: токенизация чистая; раскладка прототипа цела; нет эмодзи в
   заголовках; шрифты `clamp()`; декор не добавил структуры.

## Дерево решений «откуда брать форму/картинку»

```
Нужен визуальный элемент
│
├─ ТЕКСТ или структурный элемент?      → из прототипа 1:1. Не выдумываем.
├─ ЛИЦО человека или БРЕНД-ЗНАК?       → РЕАЛЬНЫЙ файл клиента
│                                         (фото → rembg; логотип → vtracer).
│                                         ❌ НЕ генерировать.
├─ Конкретная форма ИЗ референса?      → ТРАССИРОВАТЬ (vtracer) → currentColor.
│                                         ❌ Не «рисовать похоже на глаз».
├─ АБСТРАКТНЫЙ объект без бренда/лица? → ГЕНЕРИРОВАТЬ на хромакее → rembg.
├─ ИКОНКА?                             → inline-SVG / Lucide. currentColor.
└─ ДЕКОР-ФИГУРА (блоб, росчерк)?       → CSS border-radius / inline-SVG. currentColor.
```

**Ключ:** точную/узнаваемую вещь берут из источника, не выдумывают.
Генерация — только для абстрактного.

## Разделители между блоками

**Главное — ЕДИНООБРАЗИЕ.** На весь проект — ОДИН из двух подходов:

- **(А) Переход** — кромка в цвете одной из соседних секций, «перетекает» в другую.
- **(Б) Яркий разделитель-элемент** — заметная форма/цвет, но тогда **на всех
  стыках одинаковый** (одна форма, один приём).

Нельзя смешивать (здесь тонкий переход, там яркая полоса, там голый стык).
Форма разделителя — одна на проект (`<symbol>`/`<use>`). **Все** переходы
между секциями оформлены — голый стык фонов = «недоделано».

## Запреты (универсальные)

| Запрет | Почему |
|---|---|
| Карточки-коробки посреди полноширинных секций | выбиваются из ритма |
| Эмодзи в заголовках | маркер «наспех»; только иконки |
| Водяные цифры-призраки «для объёма» | случайное пятно |
| Невыровненный декор | выглядит как ошибка |
| Генерация лица или логотипа | узнаваемый знак не выдумывают |
| Прямые цвета вне токенов | ломают переключатель палитры |
| Фиксированные px у шрифтов | не «дышит»; только `clamp()` |
| Декор, меняющий раскладку прототипа | галлюцинация структуры |
| Раскладку/композицию брать у референса | раскладка только из прототипа |

> **Токенизация:** ни одного прямого цвета вне `:root`. Декор красится
> `currentColor`. Исключение — мета-тег `theme-color` и фирменные иконки
> мессенджеров (WhatsApp/Telegram), зелёная точка «онлайн».
