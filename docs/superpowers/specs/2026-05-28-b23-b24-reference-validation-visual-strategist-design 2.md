# B23+B24 — Reference Validation & Visual Strategist Design

**Goal:** Устранить два системных сбоя в флоу 03→04: агент молча пропускает недоступные референсы и принимает визуальные решения без участия менеджера.

**Architecture:** Этап 03 разбивается на 03a (сбор + валидация референсов, расширенный `references-curator`) и 03b (визуальное позиционирование, новый агент `visual-strategist`). Этап 04 (`brand-architect`) получает обязательный input — утверждённый `visual-concept.md`.

**Tech Stack:** Python (style-extractor scripts), YAML (index.yaml, visual-concept.yaml), HTML (refs-palette.html preview), Bash (gate-check.sh новые чеки).

---

## Контекст и проблемы

### B23 — Агент не сообщает о недоступных референсах

**Что сейчас:** `references-curator` получает URL, не открывает его (Behance/Tilda/Instagram требуют браузер), молча пишет notes на основе названия проекта или нишевых догадок, ставит `status: approved`.

**Почему плохо:** Менеджер думает референс обработан. Brand-architect читает ложные notes и принимает дизайн-решения на их основе. Менеджер видит несоответствие только на этапе 07b — после нескольких этапов и сотен токенов.

**Пример:** lixiang-dubai3, референс OFFtrail (Behance). Notes: `"dark premium"`. Реальность: ярко-синий `#2B72B8`, Archivo Black, editorial. Результат: чёрный дизайн `#0A0A0A` вместо ожидаемого.

### B24 — Агент добавляет свои референсы без согласования

**Что сейчас:** `references-curator` самостоятельно добавляет референсы из `competitors.yaml` и нишевых дефолтов, ставит им `status: approved` без явного подтверждения менеджера.

**Почему плохо:** Нишевые дефолты (premium-auto = тёмный) перевешивают реальный референс пользователя. Менеджер не знает что именно влияло на дизайн-решения.

## Этап 03a — `references-curator` (расширение)

### Изменение 1: STOP при недоступном URL

При попытке открыть URL через WebFetch:
- **Успех** → извлекаем палитру/типографику, пишем notes
- **Неудача** (любой HTTP error, пустой HTML, JS-only страница) → **STOP**:

```
⚠️ Референс недоступен: https://www.behance.net/gallery/246960855/...
Behance требует авторизацию — я не могу прочитать визуал автоматически.

Пришли одно из:
— Скриншот страницы (перетащи в чат)
— Текстовое описание стиля (цвет фона, акценты, шрифты, настроение)

Без этого не могу корректно передать стиль в brand-kit.
```

Агент не продолжает пока не получит альтернативу для **каждого** недоступного URL.

### Изменение 2: Собственные референсы только с явного согласия

Если агент хочет добавить референсы из ниши/конкурентов — показывает список с обоснованием:

```
Я нашёл похожие референсы для ниши premium-auto в ОАЭ:
1. bmw.ae — структура модельного каталога, test drive CTA
2. mercedes-benz.ae — model-picker UX, luxury minimal
3. tesla.com/ae_en — EV-позиционирование, range-блок

Добавить в референсы? (можно выбрать часть или все)
```

Каждый получает `status: approved` только после явного "да". Без ответа — не добавляет.

### Изменение 3: Отчёт по извлечённой палитре

После обработки всех референсов — в чате таблица + HTML-файл.

**В чате** (для каждого референса):

```
📎 OFFtrail (Behance) — извлечено:

Основные цвета:
• Фон       #2B72B8  — насыщенный синий, энергичный (как спортивная форма)
• Акцент    #C9A84C  — золотисто-жёлтый, тёплый (заголовки, CTA)
• Footer    #E8407A  — ярко-розовый, игривый
• Текст     #FFFFFF  — белый на синем

Типографика:
• Заголовки: Archivo Black — жирный гротеск, uppercase, агрессивный
• Тело: не определено (нужно уточнить или предложим варианты на 03b)

Настроение: editorial, яркий, молодёжный, full-bleed фото
```

**HTML-файл** `03_РЕФЕРЕНСЫ/refs-palette.html` — цветные плашки, font specimens, рядом с каждым референсом.

Менеджер подтверждает: "да, это то что я имел в виду" → этап 03a закрывается.

### Артефакты 03a
- `03_РЕФЕРЕНСЫ/index.yaml` — как сейчас + поле `palette_extracted: true/false`
- `03_РЕФЕРЕНСЫ/refs-palette.html` — новый, HTML-превью палитр всех референсов

### Gate-check 03a (новые чеки)
- `refs_no_unresolved` — нет записей с `status: approved` и `palette_extracted: false` (т.е. нет молча пропущенных)
- `refs_palette_html_exists` — файл `refs-palette.html` создан

## Этап 03b — новый агент `visual-strategist`

### Входные данные
- `00_БРИФ/brief.md` — цель, аудитория, позиционирование
- `07_ПРОТОТИП/prototype.yaml` — структура блоков (типы блоков = боли/потребности/CTA)
- `03_РЕФЕРЕНСЫ/index.yaml` + `refs-palette.html` — утверждённые референсы с палитрой

### Процесс

**Шаг 1: Извлечение целей и эмоций**

Агент читает бриф и прототип, формулирует:
- Цель лендинга (одна фраза)
- Целевая аудитория + их ключевые боли
- Какие эмоции должен вызвать лендинг у посетителя
- Что мешает конверсии (барьеры доверия, страхи)

Показывает это менеджеру коротко — 5-7 строк. Менеджер может поправить до генерации концептов.

**Шаг 2: 2-3 визуальных концепта**

Для каждого концепта:

```
## Концепт 1: "Доверие через статус"

Эмоциональная ставка: посетитель должен почувствовать что Li Xiang — это 
не "китайский бренд", а настоящий премиум. Снимаем барьер недоверия 
через визуальный язык luxury.

Как цвет работает:
• Тёмный фон (#0A0A0A) + золото (#C9A84C) = язык Rolls-Royce / Bentley
• Белый текст на тёмном = читаемость + ощущение эксклюзивности
• Золотые CTA = "это дорого и это того стоит"

Палитра:
  Фон      #0A0A0A  — почти чёрный, глубокий
  Акцент   #C9A84C  — матовое золото
  Текст    #FFFFFF
  Surface  #161616  — тёмно-серый для карточек

Связь с референсами: дальше от OFFtrail (тот ярче), ближе к Genesis UAE
```

**Шаг 3: Выбор менеджера**

Менеджер выбирает концепт или просит скорректировать. Может сказать "нравится концепт 2, но хочу фон светлее" — агент адаптирует.

**Шаг 4: Фиксация**

Выбранный концепт → `03b_КОНЦЕПТ/visual-concept.md`:

```yaml
concept_name: "Доверие через статус"
emotional_goal: "Снять барьер недоверия к бренду через язык luxury"
palette:
  bg: "#0A0A0A"
  accent: "#C9A84C"
  text: "#FFFFFF"
  surface: "#161616"
typography_direction: "Inter, строгий гротеск, weight 700 для заголовков"
mood: ["cinematic", "luxury", "editorial"]
approved_by_manager: true
```

### Артефакты 03b
- `03b_КОНЦЕПТ/visual-concept.md` — утверждённый концепт (human-readable)
- `03b_КОНЦЕПТ/visual-concept.yaml` — машино-читаемый для brand-architect

### Gate-check 03b
- `visual_concept_approved` — `visual-concept.yaml` существует и `approved_by_manager: true`

## Этап 04 — `brand-architect` (минимальное изменение)

### Новый обязательный input
`03b_КОНЦЕПТ/visual-concept.yaml` читается первым — до любых других решений.

Агент **не выбирает** палитру — реализует уже выбранную менеджером. Его задача: взять `visual-concept.yaml` и разложить в полноценный `brand-kit.md` с токенами, шрифтами, иконками, сетками.

### Gate-check 04 (новый hard-check)
- `visual_concept_exists` — `03b_КОНЦЕПТ/visual-concept.yaml` присутствует. Без него этап 04 не открывается.
