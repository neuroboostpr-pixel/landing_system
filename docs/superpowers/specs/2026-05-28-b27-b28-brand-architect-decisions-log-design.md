# B27+B28 — Brand-Architect Routing + Decisions Log Design

**Goal:** Устранить два связанных сбоя: (1) brand-architect не различает типы правок и переделывает всё или теряется; (2) агенты принимают самостоятельные решения молча — менеджер теряет связь между концептом 03b и результатом 07b.

**Architecture:** (1) Обновить `agents/brand-architect.md` — добавить явную логику routing правок (цвет/mood → 03b, типографика/иконки → прямо в 04); (2) добавить в каждый stage-агент протокол отчёта об отклонениях от `visual-concept.yaml`; (3) обновить `landing-orchestrator` — дописывать отклонения в `<project>/decisions.log.md` после каждого `--approve`.

**Tech Stack:** Markdown (decisions.log.md), YAML (visual-concept.yaml как эталон), bash (gate-check.sh --approve hook), Python (скрипт сравнения токенов с концептом).

**Зависимости:** B23+B24 должны быть реализованы первыми — нужен `visual-concept.yaml` как эталон.

---

## Контекст и проблемы

### B27 — Нет разграничения типов правок в brand-architect

**Что сейчас:** при любом "не то" на `brand-kit.html` агент либо переделывает всё сам, либо теряется. Нет правила: какие правки локальные (типографика, иконки), а какие концептуальные (цвет, mood).

**Почему плохо:** агент может молча изменить палитру в 04 — тогда `visual-concept.yaml` и `brand-kit.md` расходятся, и всё downstream (05, 07b) строится на разных основаниях.

### B28 — Отклонения агентов не фиксируются

**Что сейчас:** brand-architect, design-system-generator, block-composer принимают самостоятельные решения (подбор шрифта, отступы, иконки) без уведомления менеджера и без записи.

**Почему плохо:** к 07b менеджер не понимает что реализация его концепта, а что агент добавил от себя. Нет возможности отследить где флоу "свернул" от задуманного.

## Дизайн B27: routing правок в brand-architect

### Два типа правок

**Концептуальные** (затрагивают `visual-concept.yaml`):
- Цвет фона, акцента, текста, surface
- Mood / эмоциональная стратегия
- Общее визуальное направление ("хочу светлее", "хочу другой характер")

**Локальные** (не затрагивают концепт):
- Типографика (семейство, вес)
- Иконки (набор, стиль)
- Мелкие токены (радиусы, отступы)

### Протокол brand-architect при получении правки

```
Менеджер: "хочу фон светлее"
                    ↓
Агент определяет тип правки
                    ↓
         Концептуальная?
        /              \
      Да               Нет
       ↓                ↓
  STOP + сообщение   Принять правку
  "Это изменение     прямо в 04,
  затрагивает        перегенерировать
  концепт. Обнови    brand-kit,
  visual-concept     записать в
  в 03b, потом       decisions.log
  вернись сюда"
```

### Сообщение при концептуальной правке (точный текст для агента)

```
⚠️ Это концептуальная правка — она затрагивает visual-concept.yaml.

Чтобы изменить [цвет фона / mood / палитру]:
1. Открой `03b_КОНЦЕПТ/visual-concept.yaml`
2. Внеси правку
3. Запусти `/landing-brand` снова — я перегенерирую brand-kit по обновлённому концепту

Если хочешь — я помогу сформулировать правку для visual-concept.yaml прямо сейчас.
```

### Ключевые слова для определения типа правки

Агент ищет в тексте менеджера:

**Концептуальные сигналы:** "фон", "background", "цвет", "colour", "color", "темнее", "светлее", "настроение", "mood", "стиль", "style", "характер", "другой концепт", "другое направление", "акцент"

**Локальные сигналы:** "шрифт", "font", "типографика", "иконки", "icons", "отступы", "радиус", "размер", "кегль"

Если непонятно → агент спрашивает: "Это правка по цвету/стилю или по шрифту/иконкам?"

## Дизайн B28: decisions.log.md

### Что такое отклонение

Отклонение = любое решение агента которое:
- Не было явно задано в `visual-concept.yaml`
- Добавлено агентом на основе собственного суждения

**Примеры отклонений:**
- "Выбрал Inter 700 как шрифт заголовков (направление в концепте: 'строгий гротеск' — конкретный шрифт не был задан)"
- "Добавил Lucide icon set (иконки не упоминались в концепте)"
- "Hero padding: 80px (нет в токенах, выбрал для cinematic mood)"

**Не отклонение:**
- "Фон: #0A0A0A (из visual-concept.yaml palette.bg)" — это реализация, не отклонение

### Протокол агента при завершении этапа

Перед `--approve` каждый stage-агент:

1. Сравнивает свои решения с `visual-concept.yaml`
2. Если есть отклонения → пишет в чат:
   ```
   ✏️ Самостоятельные решения на этом этапе:
   - Типографика: Inter 700 (концепт: "строгий гротеск", конкретный шрифт не задан)
   - Иконки: Lucide (не упоминались в концепте)
   ```
3. Если отклонений нет → молчит (не пишет "отклонений нет")
4. Передаёт список отклонений оркестратору через стандартный механизм

### `decisions.log.md` — формат

Файл: `<project>/decisions.log.md`

```markdown
# Decisions Log — <project-slug>

Журнал самостоятельных решений агентов. Фиксируется только то,
что не было задано в visual-concept.yaml явно.

---

## 04_brand — 2026-05-28 14:32

- **Типографика:** Inter 700 для заголовков, Inter 400 для body
  _(концепт задал направление "строгий гротеск", конкретный шрифт — агент)_
- **Иконки:** Lucide icon set
  _(не упоминались в концепте)_

---

## 05_design — 2026-05-28 14:45

_(нет отклонений)_

---

## 07b_composed — 2026-05-28 15:10

- **Hero padding:** 80px (стандарт 60px)
  _(выбрано для cinematic mood из концепта)_
```

### Механизм записи — оркестратор

`landing-orchestrator` после каждого `--approve`:

1. Проверяет наличие `<project>/.stage-decisions/<stage>.md` — временный файл который агент пишет если есть отклонения
2. Если файл есть → дописывает его содержимое в `decisions.log.md` с заголовком `## <stage> — <date>`
3. Удаляет временный файл
4. Если файла нет → дописывает `## <stage> — <date>\n_(нет отклонений)_`

### Скрипт `log-decisions.py`

`scripts/log-decisions.py` — вызывается оркестратором:

```
python scripts/log-decisions.py \
  --project <path> \
  --stage 04_brand \
  --decisions-file <project>/.stage-decisions/04_brand.md
```

Читает временный файл (если есть), дописывает в `decisions.log.md`.
