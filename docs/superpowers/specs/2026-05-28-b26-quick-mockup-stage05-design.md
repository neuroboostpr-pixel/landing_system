# B26 — Quick Mockup в начале этапа 05

**Goal:** Дать менеджеру возможность увидеть "как мой лендинг будет выглядеть с этими цветами" до генерации полной дизайн-системы — и итерировать пока не устроит.

**Architecture:** `design-system-generator` на этапе 05 получает новую фазу перед генерацией DESIGN.md: читает `visual-concept.yaml` + `prototype.yaml`, генерирует два варианта mockup (HTML side-by-side), итерирует с менеджером, и только после "ок" генерирует полную дизайн-систему.

**Tech Stack:** Python (mockup generator script), HTML/CSS (mockup-preview.html), YAML (visual-concept.yaml как input).

---

## Контекст и проблема

**Что сейчас:** после утверждения brand-kit.html менеджер нажимает `+` и агент сразу генерирует полный DESIGN.md + tokens.json + design-preview.html. Следующий момент когда менеджер видит реальный лендинг с этими токенами — этап 07b (composed.html), через 3-4 этапа.

**Почему плохо:** brand-kit.html показывает абстракцию — свотчи и font specimens. Менеджер не видит как #0A0A0A фон выглядит с реальным заголовком "Premium SUVs built for real life in the UAE" и золотой кнопкой. Разрыв в восприятии накапливается, и на 07b менеджер говорит "это не то что я имел в виду" — после значительных затрат.

---

**Станет:**

## Детальное описание фазы mockup

### Входные данные

- `03b_КОНЦЕПТ/visual-concept.yaml` — утверждённый концепт: палитра, типографика, mood
- `07_ПРОТОТИП/prototype.yaml` — реальный контент: заголовки, тексты, CTA

### Генерация двух вариантов

Агент генерирует **два варианта интерпретации** утверждённого концепта:

**Вариант A** — буквальная реализация концепта (точно как в `visual-concept.yaml`)

**Вариант B** — альтернативная интерпретация той же палитры:
- Если концепт тёмный → вариант B светлее (например surface `#1E1E1E` вместо `#0A0A0A`, или полностью инвертированный фон)
- Если концепт светлый → вариант B насыщеннее/контрастнее
- Типографика и акцент сохраняются, меняется только фон/surface

Цель вариантов: дать менеджеру почувствовать диапазон — не предлагать противоположные концепции, а показать как одна идея может звучать "тише" или "громче".

### Что входит в каждый вариант mockup

Два блока с реальным контентом из `prototype.yaml`:

1. **Hero-блок** — заголовок (H1), подзаголовок, два CTA, badges (если есть), placeholder для фото
2. **Первый контентный блок** после hero (trust / features / первый значимый блок по прототипу)

Достаточно чтобы почувствовать: цвет фона, типографику, акцент на кнопках, контраст текста.

### Формат `mockup-preview.html`

- Два варианта **side-by-side** на одной странице
- Над каждым — название варианта и краткое описание отличия ("A: тёмный фон / B: чуть светлее")
- Под вариантами — кнопки выбора: "Выбрать A" / "Выбрать B" / "Внести правки"
- При нажатии "Внести правки" — текстовое поле для комментария (скачивается как `mockup-feedback.txt`)

Файл: `05_ДИЗАЙН-СИСТЕМА/mockup-preview.html`

### Итерации

Если менеджер говорит "нравится A, но акцент хочу холоднее" — агент:
1. Принимает правку
2. Обновляет `mockup-preview.html` с новым вариантом
3. Показывает снова

Итераций без лимита — до явного "ок" от менеджера.

После "ок" агент фиксирует выбранные токены и генерирует полную дизайн-систему.

### Фиксация выбора

Выбранный вариант → обновляет `03b_КОНЦЕПТ/visual-concept.yaml` если были правки, затем генерирует:
- `05_ДИЗАЙН-СИСТЕМА/DESIGN.md`
- `05_ДИЗАЙН-СИСТЕМА/tokens.json`
- `05_ДИЗАЙН-СИСТЕМА/design-preview.html`

## Новый скрипт

`skills/design-system-generator/scripts/generate-mockup.py`

**Входные аргументы:**
```
--project <path>       путь к проекту
--concept <path>       путь к visual-concept.yaml
--prototype <path>     путь к prototype.yaml
--output <path>        путь для mockup-preview.html
```

**Что делает:**
1. Читает `visual-concept.yaml` → базовая палитра (вариант A)
2. Вычисляет вариант B (автоматическая альтернативная интерпретация)
3. Читает `prototype.yaml` → извлекает hero-блок и первый контентный
4. Рендерит HTML с двумя вариантами side-by-side
5. Пишет `mockup-preview.html`

## Что НЕ входит в этот spec

- Изменения этапов 03a/03b (это B23+B24)
- Анимации или интерактивность в mockup (только статичный HTML)
- Mockup для мобильной версии (только десктоп, достаточно для принятия решения по палитре)
- Автоматическое применение feedback из `mockup-feedback.txt` (менеджер описывает правки текстом, агент читает и применяет вручную)
