# Реестр визуальных ассетов дизайн-системы

**Status:** design (approved) · **Date:** 2026-06-22 · **Topic:** asset-registry

## Проблема

Декор-формы и ассеты (росчерки, блобы, фоны, иконки, фигуры) сейчас рождаются
**инлайн в рендере** (`SCRIBBLE = '<svg…>'`) — импровизация в коде. Следствия:
- форма примитивна (ровная дуга вместо живой кисти), «не такая стилизованная»;
- декор смешан с контентом в reveal-анимации → «появляется/пропадает», мигает;
- нет единого «что вообще нужно моду» → ассеты забываются, макет пустой или плоский.

Корень: в ДС нет **слоя ассетов** — как палитра для цвета, только для форм/картинок.
Ассеты должны быть переносимым активом: система описывает ЧТО нужно и ТРЕБОВАНИЯ,
а файлы генерируются отдельно (под нишу) и подставляются в слоты.

## Решение: два уровня

### A. Общий чеклист типов ассетов (в стандарте)

Канон «что вообще бывает», чтобы при создании ДС ни один тип не забыли. Сгруппирован
по слоям (от фона к переднему плану):

1. **Фоновый слой:** фон страницы/секции (заливка/градиент/изображение), сквозной
   декор-слой (Г8), паттерны/текстуры.
2. **Декор-формы:** блобы/органические пятна, росчерки/кисти-подчёркивания,
   обводки-кружки, геометрия (ромбы/круги/волны-разделители), нишевые элементы.
3. **Контентные ассеты:** фигуры-вырезы (PNG), фото, иконки, инфографика, логотип, фавикон.
4. **Поверхностные:** маски фото (круг/squircle/органик), glow/тени.

### B. `assets-manifest.yaml` на каждый мод (заполнение)

Для каждого ассета — поля:

| Поле | Значение |
|---|---|
| `нужен` | yes / no / optional |
| `роль_где` | где применяется (блоки) |
| `источник` | снят-с-рефа / генерится / библиотека / клиентский |
| `формат` | см. таблицу форматов ниже |
| `размеры` | конкретные (viewBox/px/набор) |
| `слой_поведение` | z-уровень; **декор стабилен, НЕ в reveal-анимации, не мигает** |
| `слот` | `{{decor:...}}` / `{{icon:...}}` / `{{bg:...}}` — куда подставляет рендер |
| `статус` | заглушка (система) / готов (файл положен) |
| `режим` | single / batch (см. ниже) |
| `бриф` | для генератора — детализация ПО ТИПУ (см. ниже) |

## Форматы по типам ассетов

| Тип | Формат | Размеры |
|---|---|---|
| Росчерки, блобы, геометрия, паттерны, волны-разделители, сквозной слой | **SVG** | viewBox + рендер-размер; перекрашивается токеном |
| Иконки | **SVG** | viewBox 0 0 48 48 (или сетка набора), моно/2-тон |
| Фигуры-вырезы людей/предметов, AI-формы со сложной текстурой | **PNG-прозрачный** | px + ретина ×2 |
| Фоновые изображения (сцены) | **PNG/JPG** | под секцию, ×2; cover, фокус не режет важное (Г7) |
| Градиенты, glow, тени | **CSS** | не файлы |
| Фавикон | **ICO + PNG-набор** | 16/32/180/512 |
| Логотип | **SVG + PNG-fallback** | векторный + растровый дубль |

## Бриф — переменная детализация по типу

- **Иконки** — КРАТКО: концепция + стиль + ниша (у пользователя свой промпт-шаблон).
  Генерируются **пакетом** (batch): 10–20 иконок на одном листе одним запросом,
  общий бриф на набор + нумерованный список (1. финплан, 2. долги, …). Постобработка:
  **нарезка листа** на отдельные файлы по слотам.
- **Фоновые изображения** — ПОДРОБНО: сцена, композиция, свет, настроение, цвета
  (токены), что в фокусе / что размыто.
- **PNG-картинки** (фигуры, иллюстрации) — ПОДРОБНО: субъект, поза, ракурс,
  фон=прозрачный, кадрирование, стиль.
- **Декор-формы** (блобы/росчерки) — СРЕДНЕ: форма + характер (живой мазок,
  переменная толщина) + токен-цвет.
- **Фавикон/лого** — КРАТКО: что отобразить + формат-набор.

Тех-требования (формат, размер, прозрачность) — строгие у всех, одинаково.

## Режимы генерации

- **single:** один файл = один бриф (фон-сцена, лого, отдельный блоб).
- **batch-sheet:** N ассетов на ОДНОМ листе = общий бриф + нумерованный список +
  шаг **нарезки** листа на файлы. Для плоских ассетов на сетке — **иконки**.
- **batch-series:** N отдельных кадров в ЕДИНОМ стиле = общий стиль-бриф (студия,
  свет, обработка, цвета-токены) + индивидуальные под-брифы (субъект/поза/ракурс),
  **без нарезки**. Для **фигур-вырезов и иллюстраций** — они в одном лендинге
  обычно одностильные, поэтому генерятся серией, а не вразнобой.

Правило: ассеты, которые должны выглядеть «из одного набора» (иконки, фигуры,
иллюстрации), генерятся batch'ем с общим стиль-брифом — это гарантирует единство
стиля. single — только для уникальных одиночных ассетов (фон-сцена, лого).

## Поток

1. При создании ДС агент проходит чеклист (A) → пишет `assets-manifest.yaml` (B)
   со слотами и **заглушками** (простые SVG/placeholder, чтобы макет не пустой).
2. Агент выдаёт **итоговый список «что сгенерировать/положить»** — все ассеты со
   статусом «заглушка», **включая контент-зависимые** (иконки фич, фавикон, логотип),
   каждый с брифом нужной детализации и тех-требованиями.
3. Пользователь генерирует файлы под нишу:
   - иконки → **batch-sheet** (лист + нарезка);
   - фигуры/иллюстрации → **batch-series** (серия в одном стиле);
   - фон-сцена, лого → **single**.
   Кладёт в `moods/<mood>/assets/` → статус «готов».
4. Рендер подставляет: готовый файл — его, иначе — заглушку.

## Структура на диске

```
moods/<mood>/
  assets-manifest.yaml      ← реестр (B): что нужно, требования, слоты, брифы, статус
  assets/                   ← сюда кладутся сгенерированные файлы
    decor/  (svg)
    bg/     (png/jpg)
    figures/(png)
    icons/  (svg, нарезанные из батча)
    brand/  (logo, favicon)
```

## Правила-связки (уже в `_REFERENCE-ANALYSIS-LOGIC.md`)

- **Декор стабилен (новое уточнение Г8):** декор-слой и декор-формы НЕ участвуют в
  reveal-анимации контента, не мигают при переключении мода. Reveal — только для
  контента (заголовки/карточки).
- Г7 (фон в своей области), Г8 (локальный vs сквозной декор), Г5 (ассет не
  деформируется) — применяются к ассетам реестра.

## Out of scope

- Сам генератор изображений (это пайплайн пользователя; система даёт брифы).
- Автонарезка батч-листа (отдельная утилита; манифест лишь помечает `режим: batch`).
- Применение реестра к рендеру `build_composed.py` (отдельный шаг после утверждения).
