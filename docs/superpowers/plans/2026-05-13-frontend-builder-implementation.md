# Frontend-builder Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a `frontend-builder` claude-agent invoked via `/landing-style` that translates DESIGN.md §5 wireframes into real per-block CSS (added back into DESIGN.md §5 as fenced ```css blocks) and rewrites each `wp-theme/blocks/lazyblock-<slug>/block.php` from skeleton into a layout-aware template.

**Architecture:** A new stage `08b_style` runs after `/landing-build` and before `/landing-deploy`. The agent edits DESIGN.md §5 in-place (one fenced ```css block per Block heading), then triggers a new thin script `extract-main-css.py` which reuses the existing `design_extractor.extract()` to regenerate `assets/css/main.css` (only — `style.css`, `functions.php`, `index.php` are not touched). Each `block.php` is overwritten with a marker comment in the header that documents the manual-edit-forbidden contract.

**Tech Stack:** Python 3 (scripts), pytest (tests), bash (gate-check, slash-commands), Claude agent markdown (`agents/frontend-builder.md`), DESIGN.md (markdown source of truth), Lazy Blocks (WordPress).

**Spec:** [`docs/superpowers/specs/2026-05-13-frontend-builder-design.md`](../specs/2026-05-13-frontend-builder-design.md)

## Convention: Per-block CSS fence in DESIGN.md §5

`frontend-builder` MUST insert exactly one fenced ```css block per `### Block N — Name (path.php)` heading in §5. Insertion point: at the very end of the block's section, after the last existing prose paragraph, preceded by a new `**CSS:**` line. The fenced block contains all rule bodies (including `@media` queries) for that block's BEM classes.

Example after frontend-builder pass:

```markdown
### Block 1 — Hero (`block-hero.php`)

... existing prose, wireframes, ACF fields ...

**CSS:**

​```css
.hero { display: grid; gap: var(--space-8); }
.hero__title { font-size: var(--fs-h1); color: var(--text-primary); }
@media (min-width: 768px) {
  .hero { grid-template-columns: 1fr 1fr; align-items: center; }
}
​```
```

The existing `design_extractor.extract()` already finds these fenced blocks because it scans all of §5 indiscriminately. No extractor change required.

## Marker comment for `block.php`

Every `block.php` written by `frontend-builder` MUST start with:

```php

// Edits will be overwritten. Modify DESIGN.md §5 or block-spec.yaml instead.
```

This is the contract from spec §4 Q3.

#!/usr/bin/env python3
"""Verify every block.php under wp-theme/blocks/lazyblock-* starts with the
frontend-builder marker comment.

Exit 0: all blocks have marker (or no blocks present).
Exit 1: at least one block.php is missing the marker.

Usage: check-block-php-markers.py <project-dir>
"""
import sys
from pathlib import Path

MARKER_LINES = (
    "<?php",
    "// AUTO-GENERATED by frontend-builder.",
    "// Edits will be overwritten. Modify DESIGN.md §5 or block-spec.yaml instead.",
)


def main(argv: list) -> int:
    if len(argv) < 2:
        print("usage: check-block-php-markers.py <project-dir>", file=sys.stderr)
        return 2
    project = Path(argv[1])
    blocks_dir = project / "08_КОД" / "wp-theme" / "blocks"
    if not blocks_dir.exists():
        return 0
    missing: list[str] = []
    for block_php in sorted(blocks_dir.glob("lazyblock-*/block.php")):
        text = block_php.read_text(encoding="utf-8")
        head = "\n".join(text.splitlines()[:3])
        if not all(line in head for line in MARKER_LINES):
            missing.append(block_php.parent.name)
    if missing:
        print(f"missing frontend-builder marker in: {', '.join(missing)}", file=sys.stderr)
        return 1
    return 0


if __name__ == "__main__":
    sys.exit(main(sys.argv))
```

#!/usr/bin/env python3
"""Verify every `### Block N — Name` heading in DESIGN.md §5 has at least one
fenced ```css block in its body.

Exit 0: all blocks have CSS fence.
Exit 1: §5 missing, or at least one Block heading lacks CSS.

Usage: check-section5-css.py <project-dir>
"""
import re
import sys
from pathlib import Path


_H2_RE = re.compile(r"^##\s+(\d+)(?:\.\d+)*\.?\s+.*$", re.MULTILINE)
_H3_BLOCK_RE = re.compile(r"^###\s+(Block\s+\d+[^\n]*)", re.MULTILINE)
_CSS_FENCE_RE = re.compile(r"```css\n.*?\n```", re.DOTALL)


def _extract_section5(md: str) -> str | None:
    matches = list(_H2_RE.finditer(md))
    for i, m in enumerate(matches):
        if int(m.group(1)) == 5:
            start = m.end()
            end = matches[i + 1].start() if i + 1 < len(matches) else len(md)
            return md[start:end]
    return None


def _split_blocks(section5: str) -> list[tuple[str, str]]:
    """Return [(heading, body), ...] for each `### Block N ...` in §5."""
    matches = list(_H3_BLOCK_RE.finditer(section5))
    out = []
    for i, m in enumerate(matches):
        head = m.group(1).strip()
        body_start = m.end()
        body_end = matches[i + 1].start() if i + 1 < len(matches) else len(section5)
        out.append((head, section5[body_start:body_end]))
    return out


def main(argv: list) -> int:
    if len(argv) < 2:
        print("usage: check-section5-css.py <project-dir>", file=sys.stderr)
        return 2
    project = Path(argv[1])
    md_path = project / "05_ДИЗАЙН-СИСТЕМА" / "DESIGN.md"
    if not md_path.exists():
        print(f"DESIGN.md not found: {md_path}", file=sys.stderr)
        return 1
    md = md_path.read_text(encoding="utf-8")
    section5 = _extract_section5(md)
    if section5 is None:
        print("DESIGN.md has no `## 5.` section", file=sys.stderr)
        return 1
    blocks = _split_blocks(section5)
    if not blocks:
        print("DESIGN.md §5 has no `### Block N` headings", file=sys.stderr)
        return 1
    missing = [head for head, body in blocks if not _CSS_FENCE_RE.search(body)]
    if missing:
        print(f"Blocks in §5 missing fenced ```css: {', '.join(missing)}", file=sys.stderr)
        return 1
    return 0


if __name__ == "__main__":
    sys.exit(main(sys.argv))
```

# frontend-builder

You translate DESIGN.md §5 wireframes into production visual code for one landing project.

## Inputs (read-only)

- `05_ДИЗАЙН-СИСТЕМА/DESIGN.md` — wireframes §5, tokens §2, layout §3-§4, motion §7, a11y §8, state-machines §9. Single source of truth.

- `01a_АНАЛИЗ_НИШИ/landing-structure.md` — block contract.
- `08_КОД/block-spec.yaml` — list of blocks, controls, BEM classes.
- `08_КОД/wp-theme/blocks/lazyblock-<slug>/block.php` — current skeleton (reference).

## Outputs (you write)

1. **`05_ДИЗАЙН-СИСТЕМА/DESIGN.md` §5** — add exactly one fenced ` ```css ` block per `### Block N — Name (...)` heading. Insertion point: at the very end of the block's existing section (after all prose, wireframes, ACF fields, behavior notes), preceded by a `**CSS:**` line. Content: every rule body needed for that block (selectors from "CSS-классы:" line in the same block), including `@media` queries derived from §3.3 breakpoints and any mobile wireframe present in the block. Use only CSS variables defined in DESIGN.md §2.

2. **`08_КОД/wp-theme/blocks/lazyblock-<slug>/block.php`** — overwrite each file completely. Start every file with this exact marker:

   ```php
   <?php
   // AUTO-GENERATED by frontend-builder.
   // Edits will be overwritten. Modify DESIGN.md §5 or block-spec.yaml instead.
   ```

   Then emit the block markup matching the wireframe in DESIGN.md §5 for that block. Use Lazy Blocks `$attributes` for controls per `block-spec.yaml`. Use BEM classes from the "CSS-классы:" line. Zero JS — use `<details>`/`<summary>` for accordions, `position: sticky` + CSS for sticky CTAs, checkbox-hack or `<details>` for mobile burger.

## What you do NOT touch

- DESIGN.md §1-§4, §6-§9 (designer-only).
- `block-spec.yaml` (manager-only).
- `style.css`, `functions.php`, `index.php` (pipeline).
- `assets/js/*` (zero-JS by default; if you believe JS is required, leave a `// TODO: needs JS — discuss with manager` comment in `block.php`, do not write JS).
- `page-content.html` seed.
- `landing-structure.md`, `brand-kit.md`, `tokens.json`.

## Algorithm

Process blocks one at a time, sequentially, in the order they appear in `block-spec.yaml`:

1. Read the block's entry from `block-spec.yaml` (controls, BEM class root, `wrapper_open_html` if any).
2. Read the corresponding `### Block N — Name` section from DESIGN.md §5: wireframe ASCII (desktop + mobile if present), `**Элементы:**` list, `**CSS-классы:**` list, `**Behavior:**` notes.
3. Read the current `block.php` skeleton for reference (do not copy verbatim — rewrite).
4. Compose:
   - Fenced ```css block for §5 covering every BEM class. Media queries derived from §3.3 breakpoints + any explicit mobile wireframe. Use only `var(--*)` tokens from §2. No hard-coded colors or sizes.
   - New `block.php` with marker header + layout-aware markup matching desktop wireframe; mobile via CSS only (no PHP branching on viewport).
5. Append the fenced ```css to DESIGN.md §5 under the right heading (preceded by `**CSS:**`).
6. Overwrite `block.php`.
7. Move to the next block.

After all blocks are done, the slash command will run `extract-main-css.py` to regenerate `main.css` from the updated DESIGN.md and then gate-check.

## Rules

- **No invention.** If DESIGN.md §5 / §3.3 don't describe responsive behavior for some block, use a single-column stack as fallback, do not invent a desktop layout.
- **Tokens only.** Every color, size, radius, spacing, font: `var(--token)`. If a token doesn't exist, leave a comment `/* TODO: missing token --foo, add to DESIGN.md §2 */` and proceed with a CSS fallback expression — do not add tokens to §2 yourself.
- **Cross-cutting CSS** (forms, button hover, motion, focus-visible) lives in DESIGN.md §6-§9 and is regenerated into main.css by the pipeline. In `block.php` just use the class (`.btn`, `.btn--primary`) and rely on global rules.
- **Idempotent.** Re-running you on the same project must produce byte-identical output (modulo LLM nondeterminism — aim for stable structure).
- **Per-block flag.** If invoked with `--block <slug>`, only process that one block.
```
