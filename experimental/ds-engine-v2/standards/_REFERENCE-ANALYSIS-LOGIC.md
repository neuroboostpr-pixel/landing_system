# Логика анализа референса → перенос на свой контент

> Канон для всех `moods/<mood>/recipes.yaml`. Переопределяет «по умолчанию» решения
> агента при compose (07c). Цель: переносить РЕФЕРЕНС на ЧУЖОЙ контент по правилам,
> а не подгонять разметку под конкретную картинку (источник костылей вроде `.split()[-1]`).

## Принцип

Референс и прототип — **два разных источника**, их нельзя смешивать:
- **Референс** даёт РОЛИ зон и приёмы (вид). Его ТЕКСТ не переносится — он чужой.
- **Прототип** даёт смысловые единицы (твой текст/структура).
Перенос = сопоставить роли референса со смыслами прототипа по жёстким правилам.

## Шаг 0. Референс снимается ГЛАЗАМИ, не по памяти (ОБЯЗАТЕЛЬНО)

Любое снятие с референса — роли зон (Шаг 1), приёмы (recipes), декор-формы
(assets-manifest) — делается с ОТКРЫТЫМИ картинками референса, по факту того, что
на экране. НЕ по памяти, НЕ по истории чата, НЕ по аналогии с нишей.

Дефект: внести форму/приём, которого на рефе нет (выдумка), или пропустить тот, что
есть. Особенно при сборке `assets-manifest.yaml` — его смысл в ТОЧНОМ перечне форм,
снятых с рефа.

Правило: каждая запись, снятая с рефа, помечается источником-экраном
(`источник: снят-с-рефа NN/MM.png`). Форма, которой на рефе нет, но нужна под нишу —
помечается `источник: под-нишу (НЕ на рефе)`, не выдаётся за снятое с референса.
Перед заполнением — открыть ВСЕ экраны рефа (Read картинок), не первые 2-3.
(См. также user-memory: «не выдумывать — проверять глазами (зум)».)

**Промпт ассета — готовая строка для генератора (не «описание про бриф»).** В манифесте
поле `промпт` содержит ГОТОВУЮ строку на русском, которую копируют в генератор as-is.
НЕ «концепция = фичи прототипа», а сам текст: «иконка "{фича}", линейная, тонкая линия,
скруглённые концы, минимализм, без фона». Места ниши — плейсхолдер `{ниша}`/`{субъект}`/`{фича}`,
авто-подставляется из `market-profile.md` проекта. Детализация по типу: иконки — короткая
фраза-концепция; фоны/PNG — подробный абзац.

**Цвет в промпте — ТОЛЬКО для растровых (PNG/фото), для SVG НЕ прописывать.** SVG-формы
(росчерки, иконки, дуги, блобы, нить) перекрашиваются CSS-токеном мода — цвет в промпте
генератора лишний и вреден (генератор нарисует «вшитым» цветом, не перекрасить). Промпт
SVG описывает только ФОРМУ/СТИЛЬ. PNG/фото — гамма/свет остаются (перекраски нет).

**НИША НЕ ЗАШИВАЕТСЯ в мод (НИГДЕ — recipes, manifest, правила).** Мод и его ассеты
описывают РОЛЬ и ХАРАКТЕР (живой росчерк, фигура-вырез субъекта, тёплое фото на
закате), а НЕ содержимое ниши (питомец, лапка, золотой час с собакой). Один мод
работает на многих нишах — конкретику (что на фото/иконке/фигуре) подставляет ПРОЕКТ
из `market-profile.md`. В брифах: «субъект ниши», «знаки по фичам прототипа», не
«питомец/флакон». Описание ФАКТА рефа («на рефе 01/15 — кадр на закате») допустимо как
наблюдение, но НЕ как предписание ниши в брифе. Это та же граница, что «не лицо/пиджак»
в геометрии и «не 5 дней» в анализе: правило родовое, конкретика — из проекта.

## Шаг 1. С референса снимаем РОЛИ зон, не слова

Не «там написано PRO и ДЕНЬГИ», а: «есть **два типографских якоря** — один залит
акцентом, другой контурный, по разным краям, между ними фигура». Фиксируем РОЛЬ
(`anchor_fill`, `anchor_outline`, `figure`, `text_*`, `cta`, `object`), позицию-зону
и слой (z). Это и есть `hero_layout.zones` в рецепте мода.

## Шаг 2. Из прототипа берём СВОИ смысловые единицы и размечаем роли

Заголовок/блок прототипа разбираем на смысловые единицы (это объекты прототипа, НЕ выдумка).
Единицы — родовые роли, текст подставляется из конкретного прототипа:
- `accent_word` — главное ключевое (в H1 помечено `accent_word`)
- `action` — глагол-призыв
- `qualifier` — срок / условие / число
- `rest` — остальной хвост фразы
- (для других блоков — свои единицы: `label`, `num`, `pain`, …)

## Шаг 3. Сопоставляем по КОЛИЧЕСТВУ — без дубля

Референс хочет K зон-якорей. У прототипа есть N смысловых единиц.
- 1-й якорь = `accent_word` (всегда главное → залитый).
- 2-й якорь = **следующая по важности ОТДЕЛЬНАЯ единица** (`qualifier` → `action`),
  но НИКОГДА не часть первой.
- Если отдельной значимой единицы нет → **2-й якорь НЕ рисуем**. Один якорь корректнее дубля.
- K зон у референса > N единиц прототипа → лишние зони не заполняем выдуманным; оставляем
  пустыми или отдаём под объекты/декор.

## Шаг 4. Правило непересечения (ОБЯЗАТЕЛЬНО)

Якоря/зоны не делят одну фразу. Множества слов разных якорей не пересекаются:

    set(anchor_fill.words) ∩ set(anchor_outline.words) == ∅

Нарушение (одно слово в двух зонах, или «целое» + «его же последнее слово») = дефект.
Проверяется механически до рендера.

## Геометрия зон (общие правила, любой контент)

Зоны нельзя задавать независимыми абсолютными точками — при 5+ элементах они
наезжают. Под коллажем нужен скелет. Правила — про роли, читаемость и слои, без
привязки к содержимому фигуры, её позиции и к проекту. Правило задаёт РЕЗУЛЬТАТ;
РАСПОЛОЖЕНИЕ (где фигура, сколько коридоров, края якорей) — частное, в recipes мода.

**Г1. Холст делится на непересекающиеся зоны, у каждой одна роль** (текстовая /
фигура / декор). Конкретное расположение — где фигура, сколько зон, их доли —
задаёт рецепт мода (снято с его референса). Стандарт требует только: зоны не
пересекаются.

**Г2. Элемент на фигуре допустим, если читается.** Маленькие закреплённые
элементы (бейдж, цитата-плашка, маркер) сажают на фигуру намеренно, со своей
подложкой — это приём. Дефект — когда крупный текст или поток наезжает на фигуру
и она рвёт чтение. Критерий: читается → можно, не читается → нельзя.

**Г3. Внутри текстовой зоны — поток, не абсолют.** Элементы текстовой зоны идут
вертикальным стеком (flow, gap) — это даёт непересечение и единое выравнивание по
краю зоны (сетка). Абсолютное позиционирование — только для декора и слов-якорей,
**и только в границах своей зоны (фигуры/декора): декор-абсолют не заходит в
текстовые коридоры и не выходит за край холста.** Абсолют ≠ «где угодно». Если
декор пересёк бы текст или край — он уменьшается или смещается внутрь зоны, но не
накрывает читаемое.

**Г4. Содержимое зон не дублируется.** Текст разных зон не пересекается: ставший
крупным якорь не повторяется обычным текстом рядом. Каждая зона показывает только
то, чего нет в других (`зона_A.text ∩ зона_B.text == ∅`).

**Г5. Фигура и любой ассет не деформируются.** Картинка-вырез, фото, иконка
сохраняют исходные пропорции (`object-fit:contain/cover` + `width:auto`, либо
фиксированный аспект). Растягивать/сжимать субъект по одной оси — дефект. Не влезает
в зону — масштабируется целиком или зона подстраивается, но пропорции не ломаются.

**Г6. Композиция собрана, без провалов.** Контент читается как единый связный
блок, а не как разнесённые по краям острова. Крупный незаполненный провал между
зонами — дефект: зоны располагаются так, чтобы пустоты между ними были соразмерны
контенту. КАК добиться собранности (ограничить ширину контента, центрировать,
сузить колонки, заполнить декором) — частное мода; правило требует только результат:
нет зияющих провалов, блок связный. (Не противоречит Г1: зоны рядом, но не внахлёст.)

**Г7. Фон — отдельная роль, привязан к своей области.** У фона есть ОБЛАСТЬ (весь
холст / секция / зона / карточка — задаёт рецепт). Внутри своей области фон
полноширинный (full-bleed по ней) и лежит на нижнем слое. За границы своей области
фон НЕ выходит — обрезается по ней (`overflow:hidden` на контейнере), не залезает на
соседние (родственно Г3: неконтентные слои сидят в своей зоне). Картинка-фон
кадрируется `cover` (заполняет, не искажая — Г5), фокус не режет важное. Поверх фона
читаемость сохраняется (контраст/затемнение).

**Г8. Декор бывает двух видов — локальный и сквозной.** До Г8 декор был только
ЛОКАЛЬНЫЙ: привязан к секции, обрезается по её границе (Г3, Г7) — ромб в углу hero,
glow за фигурой. Второй вид — СКВОЗНОЙ декор-слой: тонкие линии, дуги, формы, идущие
ЧЕРЕЗ ВЕСЬ лендинг, пересекая границы секций, связывая композицию в единое полотно
(как дуги-окружности по полям реф 01, тянущиеся из секции в секцию). Два вида
подчиняются разным правилам, путать нельзя:
- *локальный* — внутри секции, не выходит за неё (Г3/Г7);
- *сквозной* — отдельный слой уровня страницы (page-level), нижний z (под секциями,
  над фоном страницы), тянется на всю высоту лендинга.
Сквозной слой НЕ нарушает Г7: его ОБЛАСТЬ — весь лендинг, и внутри неё он по Г7 не
выходит за край. Требования: не мешает читаемости (низкий контраст/opacity, нижний
слой), `pointer-events:none`, без горизонтального скролла. Применять: 1 сквозной
мотив на лендинг (нить/дуга/сетка) как связующий элемент — какой мотив, частное
мода (recipes). «Рваное», несвязное ощущение лендинга при отсутствии сквозного
слоя — сигнал, что связующий декор потерян.

**Декор СТАБИЛЕН — не участвует в reveal-анимации контента.** Декор (сквозной слой,
росчерки, блобы, дуги, glow) — это фон, он просто ЕСТЬ, а не «въезжает». Reveal
(появление по скроллу, fade-in) — ТОЛЬКО для контента (заголовки, карточки, текст).
Декор в reveal-цикле даёт дефект «появляется/пропадает», мигает при переключении
мода/перерисовке. Декор-элементы не получают класс анимации появления и не сбрасываются
при ре-обсёрве.

## Типографика текста (группа Т — поведение текста внутри блока)

Г-группа про расположение блоков, П-группа про акценты/фон — а поведение ТЕКСТА
внутри своего блока (перенос, помещение, обрезка) не покрыто ничем. Отсюда рваные
заголовки, висячие слова, обрезанные цитаты.

**Т1. Заголовок-якорь переносится по смыслу, не рвётся как попало.** Крупный
заголовок/слово-якорь (дисплейный кегль) — самый заметный текст, его разрыв виден
сразу. Дефект: одинокое короткое слово на отдельной строке («в», «и», «за», «к»),
разрыв слова переносом, рваный неровный край у центрованного заголовка. Правило:
короткий якорь (1–3 слова) — запрет разрыва (`text-wrap:nowrap` либо неразрывные
пробелы внутри); длинный заголовок — балансировка строк (`text-wrap:balance`), чтобы
строки были соразмерны и предлог не висел один. Никакая строка дисплейного заголовка
не начинается и не заканчивается одиноким служебным словом. КАК (balance / nowrap /
`&nbsp;`) — частное рендера; результат: заголовок читается цельными смысловыми кусками.

**Т2. Текст не обрезается контейнером.** Текстовый блок показывается ЦЕЛИКОМ — высота
контейнера определяется содержимым, а не наоборот. Дефект: фиксированная высота
(`height`/`max-height`) + `overflow:hidden` режет текст (обрезанная цитата/абзац);
`-webkit-line-clamp` без намерения; текст под соседним элементом. Правило: контейнеры
текста (цитаты, абзацы, заголовки, подписи) растут по контенту; обрезка допустима
ТОЛЬКО как намеренный приём (тизер «читать далее») и явно помечена. Критерий: ни один
символ контента не скрыт обрезкой случайно.

**Т3. Нет висячих предлогов и одиноких слов.** В читаемом тексте (заголовки, лиды,
абзацы) короткие служебные слова — предлоги, союзы, частицы, одно-двухбуквенные — не
остаются одни в конце строки («…план под\nвашу…») или началом строки. Правило:
связывать их с соседним словом неразрывным пробелом (`&nbsp;`) или балансировкой
строк. Особенно критично для коротких русских предлогов/союзов («в», «и», «с», «к»,
«за», «по», «не»). КАК — частное рендера (типографская обработка текста при подстановке
из прототипа); результат: строки не начинаются/не заканчиваются висячим служебным словом.

## Покрытие приёмов (акценты/декор/ритм — по ВСЕМУ лендингу, не только hero)

Самый частый дефект переноса: приёмы мода применяются в hero и обрываются —
ниже первого экрана монотонный фон, нет акцентов, «плоско». Правило:

**П1. Каждый приём рецепта применён хотя бы где-то ниже hero.** Приёмы из
`recipes.yaml` (accent_zone, headline_anchor, void_decor, card_panel.featured,
list_marker, block_divider…) — это характер мода, а не украшение hero. Если приём
есть в рецепте, он обязан проявляться по лендингу (в секциях контента), а не только
в первом экране.

**П2. Ритм зон: фон секций ОБЯЗАН чередоваться.** Если все секции лендинга имеют
один фон — это дефект «пресно, глаз не цепляется», даже когда внутри есть акценты.
Фон секций чередуется по тонам мода (напр. surface ↔ bg ↔ surface-2). Кроме того, на
лендинге обязателен минимум один **полноширинный акцент-якорь** — крупное цветное
пятно во всю ширину (акцент-зона/CTA-полоса/выделенный блок), которое «держит»
яркость (см. приём `accent_band`/`accent_zone` рецепта). Акценты только мелкие
(слово, маркер, одна карточка) при монотонном фоне — недостаточно.

**П3. Акцент-элемент в каждой смысловой группе.** Сетки (cases/process/trust)
получают акцент по правилам мода: выделенная карточка (featured), цветная зона,
крупная цифра, росчерк под заголовком — то, что описано в рецепте. Группа из
одинаковых нейтральных карточек без единого акцента — дефект.

**П4. Границы краевых блоков (шапка/футер) читаются.** Шапка и футер визуально
отделены от соседнего контента: контраст фона, разделительная линия достаточной
видимости или тень. Залипающая (sticky/fixed) шапка отделяется обязательно
(предпочтительно тень/усиление при скролле). Краевой блок того же фона, что соседняя
секция, без видимой границы — дефект «слияния».

**Проверка перед рендером:** пройти список `recipes[].id` и отметить, где каждый
приём проявляется в композиции. Приём, не нашедший места нигде кроме hero, —
сигнал, что перенос неполный.

## Шаг 5. Раскладку референса 1:1 НЕ копируем

Позиции-зоны берём как ХАРАКТЕР (слова-якоря по краям, фигура-якорь, тексты по углам,
слои), но точные координаты адаптируем под СВОИ единицы и их длину. Цель — узнаваемый
вайб композиции, не пиксельная копия (см. reference-driven-rules §1.2).

## Применение

Каждый `recipes.yaml` ссылается на этот файл в приёме `hero_layout` (и любом
зональном приёме). Агент при 07c обязан пройти шаги 1–4 прежде чем раскладывать hero.
