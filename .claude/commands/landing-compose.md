# /landing-compose

Запускает этап **07b_COMPOSED**.

## Что делает

### Шаг 07b-pre: список ассетов с промптами (NEW)

Перед отрисовкой composed.html агент **обязан** составить список ассетов для генерации:

1. Читает `05_ДИЗАЙН-СИСТЕМА/moods/<mood>/recipes.yaml` — какие объекты нужны.
2. Читает `07_ПРОТОТИП/prototype.yaml` (или `market-profile.md`) — адаптирует под нишу.
3. Создаёт `07b_COMPOSED/assets-prompts-<mood>.md` — список по правилам:
   - **SHEET** (один промпт = несколько мелких объектов на листе): иконки, скриблы, символы-декор.
   - **SINGLE** (один промпт = один файл): фигуры людей, логотип, favicon.
   - **CSS-only** (без генерации): примитивы реализованные кодом — перечислить отдельной таблицей.
   - Промпты адаптированы под нишу: профессия субъекта, стиль одежды, тематика иконок.
   - Каждому ассету — слот `{{slot:name}}` и путь назначения `assets/<type>/`.
4. Показывает список пользователю, ждёт одобрения или правок.
5. После одобрения — продолжает compose.

### Шаг 07b: compose

1. Проверяет наличие `07_ПРОТОТИП/prototype.yaml` и `05_ДИЗАЙН-СИСТЕМА/tokens.json`.
2. Передаёт работу агенту `block-composer`.
3. Сообщает путь к артефакту.

### Шаг 07b-post: визуальная проверка (ОБЯЗАТЕЛЬНО перед сдачей)

После записи composed.html — **открыть файл в браузере** и пройти по каждой секции:

1. **Горизонтальный скролл** — нет? Если есть — убрать нити с `right:-40px;overflow:visible`
   или добавить `body{overflow-x:hidden}`.
2. **Перекрывающиеся абсолютные элементы** — в каждой точке (top/right, bottom/left)
   должен находиться ровно один элемент. Проверить иконки и кнопки-стрелки.
3. **SVG-иконки** — рендерятся как stroke, не как заполненные фигуры? Если видны
   крупные залитые формы — в том месте стоит конкурирующий CSS-элемент (`.gr-arrow` и т.п.).
4. **Фигура за краем блока** — в accent_band и form_on_accent выходит за границу секции?
5. **Оранж точечный** — не более 2 секций с оранжевым фоном на весь лендинг.

**Рапортовать «готово» только после прохождения этих 5 пунктов.**
Текстовый анализ кода не заменяет браузер — дефекты layout видны только в рендере.

## Артефакты

- `07b_COMPOSED/assets-prompts-<mood>.md` — список ассетов с промптами (07b-pre, один файл на муд)
- `07b_COMPOSED/assets/` — папка для сгенерированных ассетов (иконки, фигуры, декор, бренд)
- `07b_COMPOSED/composed.html`
- `07b_COMPOSED/composed-mobile.html`
- `07b_COMPOSED/block-injection-log.md`

## Условия запуска

- tokens.json в `05_ДИЗАЙН-СИСТЕМА/` существует

## Запуск

Автоматически через `/landing-go` (рекомендуется) или вручную этой командой.
Финальный визуальный контент (фото/иконки/инфографика) добавляют этапы 07c/07d (`/landing-photos`, `/landing-visuals`).

## Стандарты этапа

- [`docs/standards/reference-driven-rules.md`](../docs/standards/reference-driven-rules.md) —
  правило трёх источников, поблочная сверка, composed.html = единственная правда о виде.
- Агент РИСУЕТ макет (коллаж, глубина), а не склеивает готовые блоки.
- **ПАНЕЛЬ МУДОВ — ОБЯЗАТЕЛЬНА в composed.html** (premium-07b-checklist §12.5):
  переключатель дизайн-систем (референсы проекта из `references-index.md` + 6
  системных `_styles/`), чтобы видеть лендинг в разных палитрах ДО публикации.
  Единый источник мудов с WP-плагином `lp-preview-panel` (превью и прод не расходятся).
  Флаг on/off (`data-preview`): едет на тестовый сайт включённой, перед продом — выкл.
  Работает только при 100% токенизации. См. reference-driven-flow-spec §2.5.
