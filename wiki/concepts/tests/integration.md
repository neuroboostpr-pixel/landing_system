# Integration Tests — интеграционные тесты пайплайна

## Что делает
Группа bats-тестов, которые проверяют сквозную логику gate-check.sh — убеждаются, что переходы между этапами работают корректно с реальными файловыми артефактами в тестовых проектах.

## Когда вызывать / в каком этапе
Тесты запускаются вручную или в CI после любых изменений в `scripts/gate-check.sh` или этапе **08b_style** (frontend-builder). Относятся к этапу 08b — «стилизация блоков».

```bash
# Bats-тесты
bats tests/integration/

# Pytest (если есть test_*.py)
pytest tests/integration/
```

## Что на вход / на выход

**Вход:**
- Временный проект (`mktemp -d`) со структурой:
  - `.landing-state.yaml` с нужными статусами этапов
  - `05_ДИЗАЙН-СИСТЕМА/DESIGN.md` с секциями `§2 Design tokens` и `§5 Per-block layouts`
  - `08_КОД/wp-theme/blocks/lazyblock-*/block.php` с маркером `AUTO-GENERATED by frontend-builder`
  - `08_КОД/wp-theme/assets/css/main.css`

**Выход:**
- Exit code `0` — все проверки прошли (gate открыт)
- Exit code `≠ 0` — gate закрыт, причина в stderr

## Покрытые сценарии

| Тест | Ожидание |
|------|----------|
| `08b_style` проходит, когда все артефакты присутствуют и маркеры на месте | exit 0 |
| `08b_style` падает, когда `block.php` не содержит маркер `AUTO-GENERATED by frontend-builder` | exit ≠ 0 |

**Важно:** текст маркера синхронизирован со скриптом `scripts/check-block-php-markers.py` — при изменении маркера нужно обновить оба места.
