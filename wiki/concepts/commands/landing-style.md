# landing-style — Перевод wireframes в production CSS и block.php

## Что делает

Команда берёт wireframe-схемы из DESIGN.md §5 и превращает их в готовый визуальный код: добавляет CSS в каждый блок, перезаписывает шаблоны `block.php` для Lazy Blocks и регенерирует `main.css`. После этого лендинг выглядит так, как задумал дизайнер.

## Когда вызывать / в каком этапе

Вызывается на этапе **08b** — после того как stage `08_build` подтверждён (`/landing-build` завершён и одобрен). Разблокирует следующий этап — `/landing-deploy`.

Запуск:
```
/landing-style               # все блоки
/landing-style --block hero  # один конкретный блок
```

## Что на вход / на выход

**Вход:**
- `05_ДИЗАЙН-СИСТЕМА/DESIGN.md` с заголовками `### Block N — Name` в §5
- `08_КОД/block-spec.yaml` — список блоков для стилизации
- Скелеты `wp-theme/blocks/lazyblock-*/block.php` (уже существующие после build)
- Токены дизайн-системы (§2, §3 DESIGN.md)

**Выход:**
- **DESIGN.md §5** — под каждым `### Block N` добавляются fenced ` ```css ` блоки
- **`block.php`** — каждый файл перезаписывается с маркером `// AUTO-GENERATED by frontend-builder` и layout-aware разметкой
- **`assets/css/main.css`** — полностью регенерируется из обновлённого DESIGN.md

## Связанные концепты

- [[frontend-builder]] — агент, который выполняет основную работу: читает wireframes, пишет CSS, перезаписывает block.php
- [[landing-build]] — предыдущий этап; должен быть approved, иначе команда останавливается
- [[landing-deploy]] — следующий этап, разблокируется после approve 08b
- [[landing-design]] — этап 05; если агент оставил `/* TODO: missing token */` — нужно добавить токен там и перезапустить
