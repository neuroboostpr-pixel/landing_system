# Landing Style — Перевод Wireframes в Production CSS (Stage 08b)

## Что делает

Превращает wireframe-схемы из DESIGN.md §5 в рабочий CSS и PHP-шаблоны для каждого блока лендинга. После запуска каждый блок получает свои стили, а `main.css` автоматически пересобирается.

## Когда вызывать / в каком этапе

Этап `08b_style`. Вызывается вручную после того, как stage `08_build` отмечен как `approved`. Разблокирует следующую команду `/landing-deploy`.

Признаки, что пора запускать:
- `/landing-build` завершён и одобрен
- В `block-spec.yaml` есть список блоков без CSS
- В `DESIGN.md §5` присутствуют заголовки `### Block N`, но нет фenced ` ```css ` блоков

Запуск всех блоков: `/landing-style`
Перегенерация одного блока: `/landing-style --block hero`

## Что на вход / на выход

**Вход:**
- `05_ДИЗАЙН-СИСТЕМА/DESIGN.md` — wireframes §5, токены §2–§3 (должны быть `### Block N — Name` заголовки)
- `08_КОД/block-spec.yaml` — список блоков для стилизации
- `08_КОД/wp-theme/blocks/lazyblock-*/block.php` — скелеты блоков (от `/landing-build`)
- brand-kit, landing-structure — контекст для агента

**Выход:**
- `05_ДИЗАЙН-СИСТЕМА/DESIGN.md §5` — под каждым `### Block N` добавляется fenced ` ```css ` блок с медиа-запросами
- `08_КОД/wp-theme/blocks/lazyblock-<slug>/block.php` — перезаписан с маркером `// AUTO-GENERATED by frontend-builder` и layout-aware разметкой
- `08_КОД/wp-theme/assets/css/main.css` — полностью регенерирован из обновлённого DESIGN.md

**HARD GATE (автоматический):** все четыре чека `gate-check.sh --stage 08b_style` должны пройти (`design_md`, `block_php_markers`, `section5_has_css`, `main_css_regenerated`).

**HARD GATE (ручной визуальный):** открыть превью в браузере, убедиться что hero/pricing/FAQ/цвета совпадают с wireframe. После → `--approve`.
