# /landing-start — Главная точка входа для нового лендинга

## Что делает

Запускает интерактивный мастер (wizard), который объясняет систему, создаёт папку проекта со всей структурой и проводит маркетолога через 4 шага подготовки материалов — прежде чем начнётся любая автоматика.

## Когда вызывать / в каком этапе

Вызывается вручную один раз — в самом начале, до любых других `/landing-*` команд. Подходит для тех, кто впервые работает с системой. Опытные пользователи могут использовать `/landing-new <slug>` напрямую.

## Что на вход / на выход

**Вход:** никаких аргументов — wizard сам задаёт вопросы.

**Выход:**
- Папка `~/Lendings/<slug>/` с 18 подпапками и README-подсказками внутри каждой.
- Материалы, разложенные по нужным папкам:
  - 🔴 `prototype.pdf` / `.md` → `07_ПРОТОТИП/source/` *(обязательно)*
  - 🟡 Фото клиента → `07c_PHOTOS/inbox/` *(рекомендуется)*
  - 🟡 Логотип → `04_БРЕНД/logos/` *(рекомендуется)*
  - ⚪ Референсы → `03_РЕФЕРЕНСЫ/` *(опционально)*
- Подтверждение проверки материалов через `wizard-check-materials.py`.
- Финальная подсказка запустить `/landing-go`.

Wizard **не запускает** `/landing-go` автоматически — только советует.

Если прототип не предоставлен — wizard завершается с ошибкой (exit 1). Остальные материалы можно пропустить: AI подберёт или сгенерирует сам.

## Связанные концепты

- [[landing-onboarding-wizard]] — агент, который непосредственно исполняет шаги wizard'а
- [[landing-go]] — следующий шаг после wizard: оркестратор всего pipeline
- [[landing-new]] — упрощённая альтернатива для опытных пользователей (без онбординга)
