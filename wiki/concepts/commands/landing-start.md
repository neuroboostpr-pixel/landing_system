# /landing-start — Онбординг-визард

## Что делает

Главная точка входа в landing-system для нового проекта. Запускает интерактивный wizard, который объясняет систему маркетологу, создаёт папку проекта (`~/Lendings/<slug>/`) с 18 подпапками и README-подсказками внутри каждой, а затем проводит через 4 шага по сбору материалов: прототип, фото клиента, логотип и референсы. После каждого шага проверяет, что файлы действительно положены на место. Финиширует подсказкой запустить `/landing-go`.

## Когда вызывается

Вызывается вручную маркетологом или проджект-менеджером в начале нового проекта — особенно если человек впервые работает с системой. Альтернатива `/landing-new` для тех, кто хочет онбординг с объяснениями, а не голое создание папки.

## Вход → выход

**Вход:** никаких аргументов и предварительных файлов не нужно — wizard сам спросит имя проекта (kebab-case slug).

**Выход:** созданная папка `~/Lendings/<slug>/` со структурой template (18 подпапок), заполненными README, и материалами клиента, разложенными по правильным местам. По завершении пользователь знает, что делать дальше (`/landing-go`).

## Failure modes

- **Прототип не найден** — wizard завершается с exit 1; без `prototype.pdf` или `.md` в `07_ПРОТОТИП/source/` продолжение невозможно.
- **Пользователь вводит slug не в kebab-case** — wizard может создать папку с некорректным именем, что ломает последующие этапы (нет явной валидации в описании).
- **Папка уже существует** — если `~/Lendings/<slug>/` уже есть, поведение wizard не описано; возможен конфликт или перезапись README.
- **Файлы положены не туда** — проверка через `wizard-check-materials.py` поймёт ошибку, но пользователь-новичок может растеряться при неясном сообщении об ошибке.
- **Wizard завершился, но `/landing-go` не запущен** — wizard намеренно не запускает следующий шаг автоматически; пользователь может забыть сделать это вручную.
