# /landing-content — Адаптация текстов прототипа под Gutenberg-блоки

## Что делает

Берёт текст из утверждённого прототипа и раскладывает его по Gutenberg-блокам, определённым в `DESIGN.md`. Параллельно готовит SEO-копии: заголовки, мета-описания и варианты h1 для поисковых систем.

## Когда вызывать / в каком этапе

Запускается на этапе **07 (Контент)**, после того как утверждён стек (`/landing-stack` → `06_СТЕК/design-stack.yaml`). Перед вызовом система проверяет:

1. Пройден ли onboarding (`~/.landing-system/setup_complete`); если нет — предлагает `/landing-onboarding`.
2. Gate-check для `--stage 07_content` через `gate-check.sh`; если предыдущий этап не закрыт — сообщает, что именно не готово.

После того как пользователь одобряет результат, команда вызывает `gate-check.sh --approve`, открывая путь к этапу 08 (`/landing-build`).

**HARD GATE:** команда показывает `final-copy.md` и ждёт явного одобрения пользователя — автоматического перехода к сборке нет.

## Что на вход / на выход

**Входные артефакты:**
- `07_ПРОТОТИП/prototype.md` — нормализованный прототип с текстами (создаётся командой `/landing-prototype`)
- `DESIGN.md` — структура Gutenberg-блоков (создаётся командой `/landing-design`)
- `06_СТЕК/design-stack.yaml` — утверждённый стек
- `02_МАТЕРИАЛЫ_КЛИЕНТА/testimonials/` — реальные отзывы клиента (если есть)

**Выходные артефакты:**
- `07_КОНТЕНТ/final-copy.md` — финальные тексты, разложенные по каждому блоку
- `07_КОНТЕНТ/seo-copy.md` — SEO-варианты: title, description, h1

## Связанные концепты

- [[content-writer]] — агент, которого диспатчит команда для фактического написания текстов
- [[prototype-importer]] — создаёт `prototype.md` на предыдущем этапе 07
- [[landing-stack]] — предшествующая команда, создаёт `design-stack.yaml` (обязательный вход)
- [[landing-build]] — следующая команда после одобрения контента (этап 08)
- [[landing-wireframe]] — создаёт визуальную структуру блоков, которую контент-врайтер учитывает
