# /landing-new — Создание нового проекта лендинга

## Что делает

Создаёт новый проект лендинга «с нуля»: разворачивает папку из шаблона, инициализирует файл состояния `.landing-state.yaml` и передаёт управление оркестратору для прохождения Этапа 00 (бриф). Предназначена для опытных пользователей — новичкам рекомендуется `/landing-start`.

## Когда вызывать / в каком этапе

Вызывается вручную в самом начале работы, до любых этапов. Синтаксис:

```
/landing-new <project-slug> [--cinematic]
```

- `project-slug` — идентификатор проекта в kebab-case (например, `lp-kurs-marafon`)
- `--cinematic` — опциональный флаг для включения cinematic-режима (premium)

Перед запуском команда проверяет, пройден ли онбординг (`~/.landing-system/setup_complete`). Если нет — останавливается с подсказкой запустить `/landing-onboarding`.

## Что на вход / на выход

**Вход:**
- Аргумент `<project-slug>` — имя проекта (kebab-case)
- Опционально: флаг `--cinematic`
- Готовый онбординг (файл `setup_complete`)

**Выход:**
- Папка проекта `~/Lendings/<slug>/` со структурой из 18 подпапок (по шаблону `template/`)
- Файл `.landing-state.yaml` с полями `project` и `created`
- Пройденная проверка `gate-check` для Этапа 00 (наличие `brief.md`)
- Запущенный агент `landing-orchestrator` для ведения через Этап 00

**Логика пути:** если `slug` — абсолютный или относительный путь, используется как есть. Иначе папка создаётся в `~/Lendings/<slug>/`.

## Связанные концепты

- [[landing-project-init]] — скилл, который содержит основной скрипт `init.sh`, выполняющий развёртывание шаблона
- [[landing-orchestrator]] — агент, которому команда передаёт управление после создания папки проекта
- [[gate-check]] — скрипт проверки готовности этапа; вызывается для валидации Этапа 00 после инициализации
- [[landing-start]] — альтернативная команда-wizard для новичков, более интерактивная и подробная
- [[landing-state]] — файл `.landing-state.yaml`, фиксирующий статус всех 13 этапов проекта
