# /landing-rollback — Откат лендинга к предыдущей версии

## Что делает

Восстанавливает WordPress-тему из ранее сохранённого снапшота и сразу же деплоит её на сервер. Позволяет быстро вернуться к рабочему состоянию сайта, если после обновления что-то пошло не так.

## Когда вызывать / в каком этапе

Используется на этапе **09 (деплой / ops)** — после того как лендинг уже находится в продакшне. Вызывать вручную в папке проекта, если нужно срочно откатить изменения:

```
/landing-rollback v1.0
```

Аргумент — метка версии (например, `v1.0`, `v2.3`). Если аргумент не указан, команда сначала покажет список доступных версий из папки `09_ВЕРСИИ/`.

## Что на вход / на выход

**Вход:**
- Метка версии для восстановления (например, `v1.0`)
- Сохранённые снапшоты в `09_ВЕРСИИ/<version>/wp-theme/`
- Скрипт деплоя `scripts/deploy.sh`

**Выход:**
- Восстановленный `08_КОД/wp-theme/` из выбранной версии
- Переразвёрнутый сайт на сервере (Бегет)
- Подтверждение доступности сайта после отката

**Шаги выполнения:**
1. Список доступных версий: `ls 09_ВЕРСИИ/`
2. Копирование темы: `cp -r 09_ВЕРСИИ/<version>/wp-theme 08_КОД/wp-theme`
3. Деплой: `scripts/deploy.sh .`
4. Проверка доступности сайта

## Связанные концепты

- [[lifecycle-keeper]] — агент, управляющий версиями, снапшотами и клонами лендинга; создаёт артефакты в `09_ВЕРСИИ/`, которые использует эта команда
- [[wp-deployer]] — агент деплоя на Бегет через SSH+rsync+wp-cli; вызывается внутри `scripts/deploy.sh`
- [[landing-clone]] — смежная ops-команда для клонирования проекта под A/B-тест
