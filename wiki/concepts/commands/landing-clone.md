# Landing Clone — A/B-копия лендинга на новом поддомене

## Что делает

Создаёт независимую копию существующего лендинга на новом поддомене — для A/B-тестирования или разработки сегментированной версии. После клонирования новый сайт сразу деплоится на Бегет и становится доступен по отдельному URL.

## Когда вызывать / в каком этапе

Вызывается вручную после того, как основной лендинг задеплоен и работает. Типичный сценарий — нужна копия для эксперимента с другим оффером, аудиторией или дизайном без затрагивания оригинала. Команда выполняется из папки проекта-лендинга.

```
/landing-clone <new-slug>
```

## Что на вход / на выход

**Вход:**
- `<new-slug>` — kebab-case имя нового поддомена (например, `russian` или `ab-test-v2`)
- Текущая папка проекта с рабочим `.env` и задеплоенным лендингом

**Выход:**
- Клонированная папка проекта с независимыми файлами
- Обновлённый `BEGET_PATH` в `.env` клона — указывает на новый поддомен
- Новый сайт, задеплоенный на Бегет через `/landing-deploy`
- Сообщение с URL нового лендинга

**Внутри команда делает три шага:**
1. Запускает `clone-landing.sh <project-dir> <new-slug>` — копирует артефакты проекта
2. Прописывает новый `BEGET_PATH` в `.env` клона под новый поддомен
3. Запускает `/landing-deploy` в контексте клона — публикует сайт
