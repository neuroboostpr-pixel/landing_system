# landing-clone — клонирование лендинга на новый поддомен

## Что делает

Создаёт независимую копию существующего лендинга на новом поддомене — готовую к деплою за один шаг. Используется для A/B-тестирования или быстрого разворачивания нового сегмента аудитории на основе готового проекта.

## Когда вызывать / в каком этапе

Вызывается вручную в любой момент после того, как исходный лендинг задеплоен и работает. Типичные сценарии:

- нужна A/B-версия страницы с другим оффером или дизайном;
- нужен новый сегмент ЦА (`/landing-segment`) поверх уже готового проекта;
- клиент хочет быстрый «клон» без прохождения всех этапов заново.

Запускается внутри папки проекта командой:

```
/landing-clone <new-slug>
```

## Что на вход / на выход

**Вход:**
- `<new-slug>` — имя нового поддомена / сегмента в kebab-case.
- Текущая папка проекта с настроенным `.env` и задеплоенным оригинальным лендингом.

**Выход:**
- Клонированная папка проекта с обновлённым `BEGET_PATH` в `.env`.
- Лендинг задеплоен на новый поддомен через `landing-deploy`.
- В терминале — URL новой копии.

**Шаги выполнения:**
1. Запускает `clone-landing.sh <project-dir> <new-slug>`.
2. Обновляет `BEGET_PATH` для нового поддомена в `.env` клона.
3. Вызывает `/landing-deploy` для клонированного проекта.
4. Выводит итоговый URL нового лендинга.

## Связанные концепты
