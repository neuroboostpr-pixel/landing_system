# Landing Clone — создание A/B-копии лендинга

## Что делает

Создаёт независимую копию существующего лендинга на новом поддомене — для A/B-тестирования или запуска параллельного варианта. Копия полностью автономна: имеет собственный путь на сервере и собственный URL.

## Когда вызывать / в каком этапе

Вызывается вручную после того, как основной лендинг уже задеплоен. Типичный сценарий — маркетолог хочет протестировать альтернативный заголовок, оффер или дизайн без риска для основного сайта. Запускается из папки исходного проекта-лендинга.

```
/landing-clone <new-slug>
```

Где `<new-slug>` — короткое kebab-case имя для нового поддомена (например, `my-project-v2`).

## Что на вход / на выход

**Вход:**
- Существующая папка проекта-лендинга (текущая директория)
- Аргумент `<new-slug>` — имя клона

**Выход:**
- Клонированная папка проекта с независимой структурой
- Обновлённый `.env` клона с новым значением `BEGET_PATH` (поддомен)
- Задеплоенный сайт на новом поддомене
- Отчёт с URL нового сайта

## Шаги выполнения

1. Запускает `clone-landing.sh <project-dir> <new-slug>` — копирует всю структуру проекта.
2. Обновляет `BEGET_PATH` в `.env` клона — прописывает новый поддомен.
3. Запускает `/landing-deploy` внутри клонированного проекта — деплоит на сервер.
4. Возвращает новый URL клона.

## Связанные концепты

- [[landing-deploy]] — используется на шаге 3 для деплоя клона на Бегет
- [[lifecycle-keeper]] — агент, управляющий версиями, снапшотами и клонами лендингов
- [[landing-rollback]] — команда для отката к предыдущей версии (смежный lifecycle-сценарий)
