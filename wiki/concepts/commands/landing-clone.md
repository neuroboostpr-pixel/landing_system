# Клонирование лендинга

## Что делает

Создаёт независимую копию существующего лендинг-проекта на новом поддомене — для A/B-тестирования или сегментации аудитории. Запускает скрипт `clone-landing.sh`, который копирует всю папку проекта с заменой slug'а, затем обновляет `BEGET_PATH` в `.env` клона под новый поддомен и деплоит скопированный проект через `/landing-deploy`. По завершении выводит URL нового сайта.

## Когда вызывается

Вызывается вручную внутри папки лендинг-проекта командой `/landing-clone <new-slug>`, когда нужно создать отдельную версию лендинга — например, для другого сегмента ЦА или варианта A/B-теста. Предполагается, что исходный проект уже задеплоен и работоспособен.

## Вход → выход

**Вход:** существующая папка лендинг-проекта с рабочим `.env` (включая `BEGET_PATH` и SSH-реквизиты Бегета), новый slug для клона.

**Выход:** новая папка проекта с клонированными файлами и обновлённым `.env`; готовый WordPress-сайт на новом поддомене Бегета; URL задеплоенного клона в выводе.

## Failure modes

- Скрипт `clone-landing.sh` падает, если папка с `new-slug` уже существует — нужно выбрать уникальное имя.
- `BEGET_PATH` для нового поддомена может не совпадать с автоматически подставленным значением — требует ручной правки `.env` клона.
- `/landing-deploy` завершается с ошибкой, если SSH-ключи или переменные окружения не настроены для нового поддомена.
- При клонировании мультисайт-проекта структура поддоменов Бегета может быть несовместима с автоматическим `BEGET_PATH` — нужна ручная миграция через `wp-multisite`.
- Изменения в исходном проекте после клонирования не синхронизируются автоматически — клон живёт независимо.
