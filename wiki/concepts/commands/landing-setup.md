# landing-setup — Одноразовая инициализация системы

## Что делает

Настраивает всё окружение landing-system за один сеанс: проверяет зависимости, собирает API-ключи, прописывает параметры интеграций. После успешного прогона система готова создавать проекты.

## Когда вызывать / в каком этапе

Запускается **один раз** — сразу после клонирования репозитория, до любой команды `/landing-new` или `/landing-start`. Повторный запуск безопасен: скрипты идемпотентны.

## Что на вход / на выход

**Вход:**
- Интерактивные ответы пользователя на вопросы о ключах (Firecrawl, CRM, Beget/SSH, аналитика)
- Существующий файл `.env` (если уже частично заполнен)

**Процесс (4 шага):**
1. `scripts/preflight.sh` — проверяет наличие Python, bats, wp-cli, корректность `.env`. При сбое показывает инструкции по устранению и ждёт повторного запуска.
2. Заполнение `.env` — поочерёдный сбор API-ключей для всех активных интеграций.
3. Настройка `config/system.yaml` — выбор CRM-адаптеров, аналитики, библиотек блоков.
4. Финальный отчёт готовности — что подключено, что пропущено.

**Выход:**
- `.env` — заполненный файл с секретами (в `.gitignore`, не коммитится)
- `config/system.yaml` — конфигурация интеграций (коммитится в репозиторий)
- Readiness-репорт в терминале: список подключённых и недоступных сервисов
