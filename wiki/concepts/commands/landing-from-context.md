# Создание проекта из родительской папки агентства

## Что делает

Команда создаёт новый проект лендинга в `~/Lendings/<slug>/`, автоматически забирая контекст из родительской папки агентства — аудиторию, исследования, прототип и другие материалы, уже лежащие в структуре (`01_контекст/`, `05_исследования/` и т.д.). Это сокращает ручной перенос материалов: скрипт `from-context.sh` делает snapshot родительской директории и передаёт его новому проекту. После создания сразу запускается `landing-orchestrator` начиная с этапа 02 — этапы 00–01 считаются частично заполненными из снапшота.

## Когда вызывается

Вызывается вручную из терминала командой `/landing-from-context <slug>` (опционально с флагом `--cinematic`). Типичный сценарий — маркетолог находится внутри папки клиентского агентства и хочет запустить производство лендинга для конкретного продукта, не пересобирая контекст заново.

## Вход → выход

**Вход:** папка агентства с материалами клиента (исследования, прототип, аудитория) и slug нового проекта в аргументе команды.

**Выход:** новая папка `~/Lendings/<slug>/` со структурой из 13+ этапов, снапшот контекста в `01_контекст/`, активный `landing-orchestrator` на этапе 02.

## Failure modes

- Slug не передан или содержит недопустимые символы — скрипт завершается с ошибкой до создания папки.
- Скрипт `from-context.sh` не найден (`CLAUDE_PROJECT_DIR` не указан или некорректен) — команда падает без создания проекта.
- Родительская папка не содержит ожидаемой структуры (`01_контекст/`, `05_исследования/`) — снапшот создаётся пустым, этапы 00–01 не заполняются, оркестратор стартует без данных.
- Конфликт: папка `~/Lendings/<slug>/` уже существует — поведение зависит от `from-context.sh`; без явной защиты возможна перезапись.
- При работе на Windows проекты живут на `D:\AI_TEAMS\Lendings`, а не `~/Lendings` — путь нужно указывать явно.
