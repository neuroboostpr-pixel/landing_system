# /landing-qa — QA-аудит живого лендинга

## Что делает

Проверяет опубликованный лендинг по 7 критериям качества: доступность сайта, HTTPS, мета-теги, аналитика, формы, мобильная версия и производительность. Результат — отчёт в `10_QA/qa-report.md` с пометкой pass/fail по каждому критерию.

## Когда вызывать / в каком этапе

Этап **10 (QA)**. Вызывается вручную командой `/landing-qa` **после** того, как сайт задеплоен через `/landing-deploy` (этап 09). Перед запуском система проверяет:

1. Пройден ли onboarding (`~/.landing-system/setup_complete`). Если нет — просит запустить `/landing-onboarding`.
2. Наличие завершённого этапа 09 через `gate-check.sh --stage 10_qa`. Если предыдущий этап не закрыт — сообщает об ошибке и останавливается.

После успешного завершения аудита и подтверждения пользователем запускается `gate-check.sh --stage 10_qa --approve`, фиксирующий этап в `.landing-state.yaml`.

## Что на вход / на выход

**Вход:**
- Живой сайт, задеплоенный через `/landing-deploy`
- URL лендинга — берётся из `00_БРИФ/brief.md`

**Выход:**
- `10_QA/qa-report.md` — отчёт QA-аудита с результатами по 7 критериям (pass/fail по каждому)

## Связанные концепты

- [[qa-auditor]] — специализированный агент, выполняющий проверки и пишущий отчёт
- [[landing-deploy]] — предшествующая команда (этап 09), без неё QA не запустится
- gate-check — скрипт проверки gate-условий между этапами
