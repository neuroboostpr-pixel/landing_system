# content_parser.py — парсер финального контента

## Что делает

Разбирает файл `07_КОНТЕНТ/final-copy.md` на список блоков, готовых для передачи в генераторы WordPress-темы на этапе 08. Каждый заголовок второго уровня (`## `) становится отдельным блоком; поля внутри блока определяются автоматически по набору регулярных выражений.

## Когда вызывать / в каком этапе

Используется внутри пайплайна этапа 08 (сборка кода). Вызывается автоматически генераторами wp-builder и wp-gutenberg-block-builder после того, как `content-writer` создал и утвердил `final-copy.md`. Напрямую пользователем не вызывается — это внутренняя библиотека.

## Что на вход / на выход

**Вход:**
- `07_КОНТЕНТ/final-copy.md` — финальный копирайт лендинга, структурированный по блокам через заголовки `## `.

**Выход:**
- Список объектов `Block` (Python) — каждый содержит имя блока и все найденные поля с инферированными типами (текст, список, CTA, заголовок и т.д.) согласно таблице эвристик из спецификации.

## Ключевые детали реализации

- **Единственный источник истины** для всех генераторов этапа 08: и `wp-builder`, и `block.php`-шаблоны читают контент только через этот парсер.
- **Определение типа поля** — упорядоченные regex-эвристики: сначала проверяется более специфичный паттерн, потом более общий.
- **Граница блока** — строго `## ` (H2); H1, H3 и ниже не создают новых блоков.

## Связанные концепты

- [[content-writer]] — создаёт `final-copy.md`, который парсер читает
- [[wp-builder]] — основной потребитель результата парсера на этапе 08
- [[wp-gutenberg-block-builder]] — использует список блоков для генерации `block.php`
- [[landing-content]] — команда, запускающая создание `final-copy.md`
- [[landing-build]] — команда этапа 08, в рамках которой парсер вызывается
