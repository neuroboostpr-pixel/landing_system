# verify-site-url — проверка доступности задеплоенного сайта

## Что делает
Bash-скрипт делает `curl HEAD` на URL задеплоенного лендинга, взятый из файла `.landing-state.yaml`, и возвращает код выхода: успех (2xx), сайт недоступен, или конфигурация отсутствует.

## Когда вызывать / в каком этапе
Используется на этапе **10 (QA)** после деплоя на сервер (этап 09). Вызывается вручную или автоматически агентом [[qa-auditor]] как первая проверка доступности сайта перед запуском остальных QA-критериев. Также применяется в [[stage-gates]] как hard-check закрытия этапа 09.

## Что на вход / на выход

**Вход:**
- Путь к файлу `.landing-state.yaml` конкретного проекта (обязательный аргумент)
- Поле `deploy_url` внутри этого файла

**Выход (коды выхода):**
| Код | Значение |
|-----|----------|
| `0` | URL отвечает кодом 2xx — сайт доступен |
| `1` | URL недоступен или возвращает не-2xx ответ |
| `2` | Файл `.landing-state.yaml` не найден или поле `deploy_url` отсутствует |

**Пример запуска:**
```bash
bash scripts/verify-site-url.sh ~/Lendings/my-project/.landing-state.yaml
```

## Связанные концепты
- [[qa-auditor]] — агент этапа 10, вызывает этот скрипт как первый из 7 QA-критериев
- [[stage-gates]] — конфиг hard-gate этапов; доступность URL — обязательное условие закрытия этапа 09
- [[landing-deploy]] — команда деплоя (этап 09), после которой становится актуален этот скрипт
- [[wp-deployer]] — агент деплоя, записывает `deploy_url` в `.landing-state.yaml`
