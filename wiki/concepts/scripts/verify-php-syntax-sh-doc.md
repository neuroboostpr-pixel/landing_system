# verify-php-syntax — проверка синтаксиса PHP-файлов

## Что делает
Запускает встроенный PHP-линтер (`php -l`) на каждом `.php`-файле в указанной папке. Если хотя бы один файл содержит синтаксическую ошибку — скрипт завершается с ненулевым кодом, сигнализируя о проблеме.

## Когда вызывать / в каком этапе
Вызывается после этапа 08 (сборка WordPress-темы), когда `wp-builder` и `frontend-builder` сгенерировали PHP-шаблоны блоков (`block.php`) и `functions.php`. Рекомендуется запускать перед деплоем (`wp-deployer`), чтобы не отправлять на сервер код с синтаксическими ошибками. Может также использоваться как CI-проверка при любом коммите, затрагивающем PHP-файлы.

**Пример вызова:**
```bash
bash scripts/verify-php-syntax.sh wp-theme/
```

## Что на вход / на выход

**Вход:**
- `<dir>` — путь к директории с PHP-файлами (например, `08_КОД/wp-theme/`)

**Выход (exit codes):**
| Код | Значение |
|-----|----------|
| `0` | Все `.php`-файлы прошли синтаксическую проверку |
| `1` | Хотя бы один файл содержит синтаксическую ошибку |
| `2` | Директория не существует или `php` не установлен |

Вывод в stdout/stderr — стандартный вывод `php -l` с указанием файла и строки ошибки.

## Связанные концепты
- [[wp-builder]] — генерирует PHP-файлы темы и блоков, которые этот скрипт проверяет
- [[frontend-builder]] — переписывает `block.php` шаблоны; после его работы нужна проверка синтаксиса
- [[wp-deployer]] — деплоит тему на сервер; запуск verify-php-syntax до деплоя — обязательный шаг
- [[stage-gates]] — HARD GATE 08 не должен закрываться при exit code != 0
