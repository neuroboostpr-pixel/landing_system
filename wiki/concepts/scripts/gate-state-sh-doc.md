# gate-state.sh — управление состоянием этапов проекта

## Что делает
Bash-утилита для чтения и записи файла `.landing-state.yaml` в папке проекта. Позволяет получить текущий статус любого этапа, выставить новый статус, подтвердить (approve) этап или проверить, все ли нужные этапы одобрены.

## Когда вызывать / в каком этапе
Вызывается внутренне скриптами системы и агентом `landing-orchestrator` на каждом переходе между этапами. Напрямую маркетолог обычно не запускает — это низкоуровневый инструмент. Может использоваться вручную при отладке, если нужно вручную переставить статус застрявшего этапа.

## Что на вход / на выход

**Команды:**

| Команда | Аргументы | Результат |
|---|---|---|
| `get` | `<project-dir> <stage>` | Печатает текущий статус этапа (`pending`, `done`, `approved` и т.д.) |
| `set` | `<project-dir> <stage> <status>` | Записывает новый статус этапа в `.landing-state.yaml` |
| `approve` | `<project-dir> <stage>` | Выставляет статус `approved` для указанного этапа |
| `all_approved` | `<project-dir> <comma-separated-stages>` | Проверяет, все ли перечисленные этапы одобрены; возвращает exit 0 / 1 |

**Вход:** путь к папке проекта (например `~/Lendings/my-project`) и имя этапа (например `07b`, `05`).

**Выход:** строка статуса в stdout или exit-код для `all_approved`.

**Файл состояния:** `.landing-state.yaml` в корне проекта — единственный источник правды о прогрессе по 13 этапам.
