# export-palettes-to-library — экспорт палитр в глобальную библиотеку

## Что делает

Скрипт переносит цветовые палитры из конкретного проекта в общую глобальную библиотеку `presets/palettes.yaml`. Перед добавлением дедуплицирует по полю `id` — уже существующие палитры просто пропускаются.

## Когда вызывать / в каком этапе

Запускается после завершения этапа **05 (ДИЗАЙН-СИСТЕМА)**, когда дизайн-система проекта утверждена и `05_ДИЗАЙН-СИСТЕМА/palettes.yaml` содержит финальные палитры. Предполагается вызов из команды `/landing-design` или вручную — после того как `design-system-generator` сформировал `palettes.yaml` проекта.

## Что на вход / на выход

**Вход:**
- `--project <путь>` — корневая папка проекта; скрипт читает `<project>/05_ДИЗАЙН-СИСТЕМА/palettes.yaml`
- `--library <путь>` — путь к глобальной библиотеке `presets/palettes.yaml`

**Выход:**
- Обновлённый файл `presets/palettes.yaml` — с добавленными новыми палитрами (дубли по `id` игнорируются)
- В stdout: список `added: <id>` / `skipped (id already in library): <id>` + итоговое количество палитр в библиотеке
- При некорректном YAML в исходнике — выход с кодом ошибки (через `validate-palettes.py`)

**Формат YAML на выходе:** строковые значения в двойных кавычках, ключ `id` — без кавычек (plain style). Новый файл библиотеки получает заголовочный комментарий с пояснением.

## Логика дедупликации

Скрипт строит множество `existing_ids` из текущей библиотеки. Каждая палитра проекта добавляется только если её `id` ещё не встречается в библиотеке. Порядок палитр в библиотеке сохраняется (новые добавляются в конец).

## Связанные концепты

- [[design-system-generator]] — генерирует `palettes.yaml` в проекте (входной файл скрипта)
- [[brand-kit-build]] — определяет цвета бренда, из которых формируются палитры
- [[design-tokens-generation]] — токены дизайна, куда палитры попадают как переменные
