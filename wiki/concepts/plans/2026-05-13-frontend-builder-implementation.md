# Frontend-builder — генератор CSS и шаблонов блоков (этап 08b)

## Что делает

Переводит wireframe-описания из DESIGN.md §5 в реальный CSS для каждого блока и перезаписывает шаблонные файлы `block.php` для Lazy Blocks. После его работы на сайте появляются правильные сетки, типографика, цвета — всё через CSS-переменные из дизайн-системы.

## Когда вызывать / в каком этапе

Этап **08b_style** — запускается командой `/landing-style` строго после того, как этап `08_build` получил статус `approved`. Перед `/landing-deploy`. Нельзя запускать без готового скелета темы (`wp-theme/blocks/lazyblock-*/block.php`), созданного `/landing-build`.

Опциональный флаг `--block <slug>` — перестраивает только один конкретный блок.

## Что на вход / на выход

**Вход (только чтение):**
- `05_ДИЗАЙН-СИСТЕМА/DESIGN.md` — единственный источник истины: wireframes §5, токены §2, сетка §3–§4, motion §7, a11y §8
- `04_БРЕНД/brand-kit.md` — контекст бренда
- `01a_АНАЛИЗ_НИШИ/landing-structure.md` — контракт блоков
- `08_КОД/block-spec.yaml` — список блоков, контролы, BEM-классы
- `08_КОД/wp-theme/blocks/lazyblock-<slug>/block.php` — текущие скелеты (только для справки)

**Выход (агент пишет):**
1. **DESIGN.md §5** — в каждую секцию `### Block N — Name` добавляется один fenced ` ```css ` блок под заголовком `**CSS:**`, содержащий все BEM-правила и `@media`-запросы
2. **Каждый `block.php`** — полностью перезаписывается; каждый файл начинается с маркера:
   ```
   <?php
   // AUTO-GENERATED by frontend-builder.
   // Edits will be overwritten. Modify DESIGN.md §5 or block-spec.yaml instead.
   ```
3. **`assets/css/main.css`** — регенерируется скриптом `extract-main-css.py` из обновлённого DESIGN.md (файлы `style.css`, `functions.php`, `index.php` не трогаются)

**Hard-checks после работы:**
- `check-block-php-markers.py` — маркер присутствует во всех `block.php`
- `check-section5-css.py` — под каждым `### Block N` в §5 есть fenced CSS
- `main.css` существует в папке темы
