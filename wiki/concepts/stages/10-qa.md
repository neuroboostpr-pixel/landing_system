# QA-аудит

## Что делает

Этап автоматически запускается после деплоя лендинга на Бегет. Агент `qa-auditor` выполняет полный набор проверок опубликованного сайта: PageSpeed Insights, базовый accessibility-аудит и SEO-проверки. Результаты сохраняются в виде структурированного отчёта и raw-дампа Lighthouse. Этап обязателен перед переходом к финальной проверке (stage 11/12).

## Когда вызывается

Запускается автоматически оркестратором (`landing-orchestrator`) сразу после успешного закрытия этапа 09 (деплой). Никакого ручного триггера не требует — агент `qa-auditor` стартует по событию завершения деплоя.

## Вход → выход

**Вход:** задеплоенный лендинг с известным публичным URL (из артефактов этапа 09).

**Выход:**
- `10_QA/qa-report.md` — читаемый отчёт с результатами проверок (PageSpeed, доступность, SEO).
- `10_QA/lighthouse.json` — полный JSON-дамп Lighthouse-аудита для машинной обработки.

## Чем закрывается этап (gates)

- `qa_report_present` — файл `qa-report.md` существует и содержит результаты проверок.
- `lighthouse_score_pass` — Lighthouse-отчёт сгенерирован без ошибок; минимальные пороги по ключевым метрикам не нарушены.

## Failure modes

- Сайт недоступен по URL — Lighthouse/PageSpeed не могут подключиться, отчёт не генерируется; нужно убедиться, что деплой прошёл корректно и DNS разрешается.
- Низкие Lighthouse-баллы блокируют gate — необходима правка кода темы (оптимизация изображений, удаление render-blocking ресурсов) и повторный деплой.
- Неполный отчёт из-за JS-ошибок на странице — `qa-auditor` может получить частичные данные; следует проверить консоль браузера на продакшн-сайте.
- Отсутствие реального трафика/контента — accessibility-проверки могут давать ложно-позитивные результаты на страницах с заглушками.
- Версия Lighthouse в окружении устарела — расхождение с ожидаемой схемой JSON приводит к ошибке парсинга отчёта.
