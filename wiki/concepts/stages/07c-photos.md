# 07c_PHOTOS — фото клиента и обработка

## Что делает

Папка-этап принимает клиентские фотографии, автоматически классифицирует и расставляет их по слотам прототипа, генерирует недостающие визуалы и формирует итоговый набор фото для сборки сайта.

## Когда вызывать / в каком этапе

Этап **07c** запускается после утверждения этапов 05 (design-system) и 07a (wireframe). Активируется командой `/landing-photos`. Входит в PR-B (Photo Pipeline) — запускается вручную, не через `landing-orchestrator` (интеграция запланирована на PR-D).

## Что на вход / на выход

**Вход:**
- Клиентские фото в `inbox/` (7 подпапок по типу: `портреты_и_команда/`, `процесс_работы/`, `объекты_и_продукты/`, `интерьер_экстерьер/`, `до_после/`, `документы_сертификаты/`, `_свалка/`)
- Утверждённые `design-system` и `wireframe`

**Выход:**
- `intake/` — обработанные JPEG + миниатюры (HEIC конвертированы, метаданные очищены)
- `catalog.yaml` — каталог с тегами (AI-классификация)
- `selections.yaml` — расстановка фото по слотам (заполняется через `photo-board.html`)
- `processed/` — финальные фото для сайта (обрезаны под нужные пропорции: 16:9 hero, 1:1 аватары)
- `photo-board.html` — drag-drop UI для ручной корректировки расстановки
- `photo-preview.html` — превью «фото в местах макета»
- `STATE.yaml` — статусы этапов pipeline
- `.logs/` — логи AI-вызовов для аудита

После approve `selections.yaml` — `composed.html` перерендерится с реальными фото вместо placeholders.

## Ключевые правила

- **Identity-safe:** AI никогда не ретуширует и не репейнтит реальные лица клиентов. AI-генерация лиц для testimonial/team-слотов требует явной галочки `ai_approved_by_user`.
- Не класть документы с персональными данными (паспорта, договоры).
- Фото кидать в подпапки или `_свалка/`, но не прямо в `inbox/`.

## Перезапуск отдельного этапа

```bash
/landing-photos --force-stage classify   # перетегировать
/landing-photos --force-stage match      # перерасставить по слотам
/landing-photos --force-stage preview    # пересобрать превью
```
