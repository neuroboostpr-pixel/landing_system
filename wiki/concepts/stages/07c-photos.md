# 07c PHOTOS — фото клиента и фото-пайплайн

## Что делает

Принимает клиентские фотографии, классифицирует их по типу, расставляет по слотам прототипа и подготавливает финальные изображения для лендинга. Пустые слоты закрываются AI-генерацией под брендинг.

## Когда вызывать / в каком этапе

Этап **07c** — запускается вручную командой `/landing-photos` после того, как утверждены этап 05 (design-system) и 07a (wireframe). Является частью workflow PR-B (Photo Pipeline). Не вызывается автоматически через `landing-orchestrator` — интеграция запланирована в PR-D.

**Порядок запуска:**
1. Положи фотки в `inbox/` (по подпапкам или в `_свалка/`).
2. Запусти `/landing-photos`.
3. В `photo-board.html` расставь фото drag-drop, скачай `selections.yaml`.
4. Положи `selections.yaml` обратно в `07c_PHOTOS/`.
5. Проверь `photo-preview.html` — как фото лягут в макет.
6. После approve — `composed.html` перерендерится с реальными фото.

## Что на вход / на выход

**Вход:**
- Клиентские фотографии в `inbox/` (7 подпапок по типу: портреты, процесс, объекты, интерьер, до/после, документы, `_свалка/` для неопределённых)
- Утверждённые этапы 05 и 07a

**Выход:**
- `intake/` — обработанные JPEG + миниатюры (HEIC конвертированы, метаданные очищены)
- `catalog.yaml` — каталог фоток с AI-тегами
- `selections.yaml` — маппинг «фото → слот» (заполняется через `photo-board.html`)
- `processed/` — финальные фото с обрезкой под нужные пропорции (16:9 hero, 1:1 аватары и т.д.)
- `photo-board.html` — интерактивный UI для ручной расстановки
- `photo-preview.html` — превью фото в макетных местах
- `STATE.yaml` — статусы этапов пайплайна
- `.logs/` — логи AI-вызовов для аудита

## Ключевые правила

- **Identity-safe:** реальные лица клиентов AI никогда не ретуширует и не заменяет. AI-генерация лиц для testimonial/expert/team слотов требует явного флага `ai_approved_by_user`.
- Документы с персональными данными (паспорта, договоры) — не класть.
- Фотографии кладутся в подпапки `inbox/`, не в корень.
