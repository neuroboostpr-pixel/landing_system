# 05 Дизайн-система

## Что делает
Превращает бренд-кит в единый источник истины по визуальным токенам — цветам, шрифтам и отступам — и генерирует машиночитаемый файл токенов плюс HTML-превью для согласования с клиентом.

## Когда вызывать / в каком этапе
Этап 05 запускается автоматически оркестратором после утверждения этапа 04 (бренд-кит). Вручную вызывается командой `/landing-design` внутри папки проекта. Без одобрения пользователя переход к следующему этапу невозможен (hard gate).

## Что на вход / на выход

**Вход:**
- `04_БРЕНД/brand-kit.md` — утверждённый бренд-кит с палитрой, типографикой и стилевыми решениями.

**Выход:**
- `05_ДИЗАЙН-СИСТЕМА/DESIGN.md` — единый источник правды по токенам (цвета, шрифты, отступы, радиусы и т.д.).
- `05_ДИЗАЙН-СИСТЕМА/tokens.json` — машиночитаемые токены, используются на этапах 07b (compose), 07c (photos), 07e (visuals) и 08 (build).
- `05_ДИЗАЙН-СИСТЕМА/design-preview.html` — визуальный превью всей системы для согласования.

## Связанные концепты
- [[design-system-generator]] — агент, генерирующий артефакты этапа на основе brand-kit.
- [[brand-kit]] — источник исходных данных (этап 04), обязательный вход.
- [[landing-design]] — slash-команда для ручного запуска этапа.
- [[landing-compose]] — этап 07b потребляет `tokens.json` для инъекции токенов в composed.html.
- [[landing-visuals]] — этап 07e использует `tokens.json` (цвет бренда) для генерации иконок и инфографики.
- [[landing-orchestrator]] — управляет последовательностью этапов и hard-gate'ом между 04 и 05.
