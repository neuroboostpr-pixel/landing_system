# Папка памяти сессий проекта

## Что делает
Хранит накопленные знания и журналы разговоров для конкретного лендинг-проекта. Папка `memory/` создаётся внутри каждого проекта из шаблона и содержит сырые логи сессий за каждый день, скомпилированные уроки и принятые решения, концепты по конкретным техническим выборам, а также ответы из QA-скриптов. Данные конфиденциальны (клиентские детали), поэтому папка добавлена в `.gitignore` и не попадает в репозиторий автоматически.

## Когда вызывается
Файлы внутри папки создаются и обновляются **автоматически** хуками `SessionEnd` и `PreCompact` — без участия пользователя. Вручную папку не трогают; при необходимости поделиться знаниями с командой нужно вручную экспортировать нужные файлы из `compiled/`.

## Вход → выход
**Вход:** транскрипты разговоров Claude Code в рамках проекта (генерируются сессионными хуками).  
**Выход:** структурированные файлы трёх уровней — `daily/YYYY-MM-DD.md` (сырые логи), `compiled/index.md` (компиляция уроков и решений), `compiled/concepts/*.md` (концепты по выборам), `compiled/qa/` (ответы QA-скриптов).

## Failure modes
- Ручное редактирование файлов нарушает структуру, которую ожидают хуки и скрипты компиляции.
- Папка не синхронизируется в git — если потерять локальную копию, история сессий пропадёт безвозвратно.
- Клиентские детали из транскриптов могут случайно попасть в репозиторий, если `.gitignore` не настроен или папка явно добавлена в git.
- При миграции проекта на новую машину папка `memory/` не переносится автоматически вместе с git-репозиторием.
- Хуки `SessionEnd`/`PreCompact` могут не запуститься при нестандартном завершении сессии, и лог за день окажется неполным.
