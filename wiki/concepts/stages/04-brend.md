# 04_БРЕНД — Папка бренд-материалов проекта

## Что делает
Хранит все брендовые активы лендинга: логотипы клиента и автоматически сгенерированный бренд-кит с палитрой, шрифтами и иконографикой. Это «источник истины» о визуальной идентичности проекта для всех последующих этапов.

## Когда вызывать / в каком этапе
Этап **04_brand** запускается после утверждения мудборда (этап 03). Маркетолог кладёт логотипы руками через wizard `/landing-start`. Затем агент `brand-architect` читает референсы и экстрактированные стили, чтобы собрать `brand-kit.md` и `brand-kit.html`.

## Что на вход / на выход

**Вход (добавляется вручную):**
- Логотипы клиента → `04_БРЕНД/logos/`

**Вход (автоматически, из предыдущих этапов):**
- Утверждённые референсы из `03_РЕФЕРЕНСЫ/`
- Извлечённые стили из `04_БРЕНД/extracted/*.yaml` (от `style-extractor`)

**Выход:**
- `brand-kit.md` — текстовое описание бренда: палитра, типографика, иконография с полной атрибуцией источников
- `brand-kit.html` — визуальный HTML-preview бренд-кита для утверждения маркетологом

## Связанные концепты
- [[brand-architect]] — агент, который генерирует `brand-kit.md` и `brand-kit.html` из референсов и логотипов
- [[style-extractor]] — предшественник: извлекает цвета/шрифты из изображений и URL, передаёт данные brand-architect
- [[brand-kit-build]] — скилл, описывающий логику построения бренд-кита
- [[landing-start]] — wizard, через который маркетолог кладёт логотипы в `logos/` на шаге 3 онбординга
- [[moodboard-composer]] — предыдущий этап (03), который поставляет утверждённые визуальные ориентиры
- [[design-system-generator]] — следующий этап (05): читает `brand-kit.md` и генерирует `DESIGN.md` + `tokens.json`
