# brand-kit-build — Сборка бренд-кита

## Что делает

Собирает единый бренд-кит проекта из извлечённых стилевых данных: формирует файл `brand-kit.md` с полной прослеживаемостью каждого токена (цвет, шрифт, иконка — со ссылкой на источник), затем рендерит HTML-превью `brand-kit.html` с цветовыми плашками, образцами шрифтов и миниатюрами иконок.

## Когда вызывать / в каком этапе

Этап **04 — Бренд**. Вызывается агентом `brand-architect` после того, как `style-extractor` уже отработал и записал YAML-файлы в `04_БРЕНД/extracted/`. Пользователь видит результат через `brand-kit.html` и подтверждает бренд-кит перед переходом к этапу 05.

## Что на вход / на выход

**Вход:**
- `04_БРЕНД/extracted/*.yaml` — структурированные данные о палитре, шрифтах и иконках, подготовленные `style-extractor`
- `01a_АНАЛИЗ_НИШИ/` — артефакты нишевого анализа (используются для предложения подходящих палитр из библиотеки)
- `landing_system/presets/palettes.yaml` — глобальная библиотека готовых палитр

**Выход:**
- `04_БРЕНД/brand-kit.md` — каноничный бренд-кит с провенансом каждого токена
- `04_БРЕНД/brand-kit.html` — визуальный превью для согласования с клиентом
- `04_БРЕНД/palettes.yaml` — выбранный пользователем подмножество палитр (если библиотека не пуста)

**Скрипты:**
- `scripts/build.py` — синтез `brand-kit.md`
- `scripts/render-html.py` — рендер `brand-kit.html`
- `scripts/snapshot-palettes-to-project.py` — копирование выбранных палитр из глобальной библиотеки в проект

## Режимы выбора палитры

Перед синтезом агент спрашивает клиента, сколько палитр показать на согласовании:

| Режим | Описание |
|---|---|
| **1** Точечно (1–3) | клиент чётко знает стиль |
| **2** Несколько (4–6) | есть направление (рекомендуется) |
| **3** Весь каталог | клиент в поиске |

Если `palettes.yaml` пуст (новая установка) — шаг выбора пропускается, палитры создаются на этапе 05 с нуля.
