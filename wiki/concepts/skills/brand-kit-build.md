# brand-kit-build — Сборка бренд-кита

## Что делает

Скилл читает извлечённые данные стиля из папки `04_БРЕНД/extracted/*.yaml`, синтезирует файл `brand-kit.md` с полной историей происхождения каждого токена (палитра, шрифты, иконки со ссылкой на источник), а затем рендерит HTML-превью `brand-kit.html` с образцами цветов, шрифтовыми спецификами и миниатюрами иконок.

## Когда вызывать / в каком этапе

Запускается на **этапе 04 (БРЕНД)** агентом `brand-architect`. Предполагает, что данные о стиле уже извлечены в `04_БРЕНД/extracted/`. Перед финальной сборкой агент проводит диалог с пользователем о режиме выбора палитр из глобальной библиотеки (`presets/palettes.yaml`).

Три режима выбора палитр:
- **Точечно (1–3)** — клиент знает что хочет.
- **Несколько (4–6, рекомендуется)** — есть общее направление.
- **Весь каталог** — клиент в полном поиске.

Если библиотека `presets/palettes.yaml` пуста — шаг выбора пропускается, палитры создаются с нуля на этапе `/landing-design`.

## Что на вход / на выход

**Вход:**
- `04_БРЕНД/extracted/*.yaml` — данные стиля, извлечённые из изображений и URL клиента.
- `presets/palettes.yaml` (системная библиотека) — глобальный каталог палитр.
- Выбор пользователя: какие палитры включить в проект.

**Выход:**
- `04_БРЕНД/brand-kit.md` — полный бренд-кит с провенансом токенов.
- `04_БРЕНД/palettes.yaml` — срез выбранных палитр для проекта.
- `04_БРЕНД/brand-kit.html` — HTML-превью для согласования с клиентом.

## Скрипты

- `scripts/build.py` — синтезирует `brand-kit.md`.
- `scripts/render-html.py` — рендерит `brand-kit.html`.
- `scripts/snapshot-palettes-to-project.py` — копирует выбранные палитры из глобальной библиотеки в проект (флаги `--id` или `--all`).
