# visual-qa — Визуальный QA лендинга через скриншоты и AI

## Что делает

Автоматически проверяет внешний вид лендинга: делает скриншоты на десктопе и мобильном, отправляет их в codex для анализа и получает список визуальных проблем с подсказками по исправлению. При необходимости пробует починить критические CSS-ошибки самостоятельно.

## Когда вызывать / в каком этапе

Применяется на этапах **07c, 07f, 08 и 09** — то есть после сборки `composed.html` и перед финальным деплоем. Вызывается через команду `/landing-qa`:

- `/landing-qa <project>` — базовый прогон (скриншоты + анализ + отчёт)
- `/landing-qa <project> --strict` — завершает с ошибкой, если есть критические проблемы
- `/landing-qa <project> --iterate` — включает авто-фикс цикл (до 3 итераций)

Soft-check `visual_qa_passed` в stage-gating проверяет результаты этого скилла.

## Что на вход / на выход

**Вход:**
- `composed.html` в папке проекта (результат этапа 07b/07f)
- Опциональные флаги: `--strict`, `--iterate`

**Выход:**
- Скриншоты desktop (1280×800) и mobile (375×812) через Playwright
- JSON со списком issues: уровень (critical / warning / info), тип, CSS-селектор, подсказка по фиксу
- Финальный отчёт `<project>/10_QA/visual-qa-report.md`

**Авто-фикс:** разрешён только для типа `css_tweak` (inline-стиль на селектор). Изменения текста (`text_*`) и структуры блоков (`block_*`) запрещены — первые блокируются правилом content-preserve (PR-H), вторые не трогаются принципиально.
