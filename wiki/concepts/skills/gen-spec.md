# Генератор ТЗ (build-spec)

## Что делает

Создаёт файл `07b_COMPOSED/build-spec.md` — техническое задание на вёрстку макета как **mapping**: контент активного прототипа привязывается к ролям дизайн-системы. ТЗ не дублирует тексты из прототипа и не копирует параметры из дизайн-системы — только связывает их. Для каждого мода проекта формируется отдельный полный раздел (МУД 1 → все блоки, МУД 2 → все блоки). `block_instructions` из прототипа (карусель, бегущая строка) переносятся как требования к блоку.

## Когда вызывается

Вызывается на этапе 07b, после того как активный прототип зафиксирован (`meta.active: true`) и дизайн-система с мудами готова. Предшествует генерации `composed.html` скиллом `landing-compose` / `gen-html`.

## Вход → выход

**Вход:** активный прототип `07_ПРОТОТИП/prototype-*.yaml` (флаг `meta.active: true`) + папки мудов `05_ДИЗАЙН-СИСТЕМА/moods/*/` с `objects.yaml` и `compositions/*.yaml`.

**Выход:** `07b_COMPOSED/build-spec.md` — структурированное ТЗ с разделом «КОНТЕНТ ПРОТОТИПА» (таблица `Cn → ключ прототипа`) и разделами по каждому муду с маппингом `роль ДС ← C-элемент + приём`.

## Failure modes

- **Нет активного прототипа** — скил не может определить источник контента; гейт `verify-spec.py` завершается с FAIL.
- **Хексы и размеры в ТЗ** — нарушение контракта: параметры принадлежат токенам ДС, не ТЗ; гейт это ловит.
- **Тексты скопированы вручную** — при ручном переносе теряются или искажаются; обязательна ссылка на ключ прототипа.
- **`block_instructions` не перенесены** — `gen-html` генерирует неверный блок (без карусели/слайдера); гейт ловит отсутствие.
- **Выдуманные заголовки блоков** — если в прототипе нет `section_title`, нужен `block_label`-fallback или опущение; любой изобретённый текст = дефект.
- **Число разделов мудов не совпадает с мудами проекта** — гейт завершится FAIL; нужен полный раздел на каждый мод.
