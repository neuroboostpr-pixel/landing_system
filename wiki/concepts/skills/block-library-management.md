# Управление библиотекой блоков

## Что делает

Предоставляет набор утилит командной строки для поддержания актуальности общей библиотеки блоков (`block-library/`). Скилл решает три задачи: проверяет корректность главного каталога (`catalog.yaml`), валидирует схему метаданных отдельного блока (`meta.yaml`) и создаёт каркас нового блока из шаблона. Используется `ux-composer` в момент инъекции блоков в wireframe или composed.html.

## Когда вызывается

Вызывается вручную при добавлении нового блока в библиотеку, при рефакторинге существующего блока, а также в рамках автоматической проверки целостности каталога перед этапами 07a–07b. Может быть вызван любым агентом, работающим с `block-library/`.

## Вход → выход

**Вход:** путь к `catalog.yaml`, путь к директории конкретного блока с `meta.yaml`, либо параметры нового блока (`--id`, `--category`) для скаффолдинга.

**Выход:** отчёт о валидации (stdout/exit-code) или готовая директория нового блока со всеми необходимыми файлами по шаблону.

## Failure modes

- `validate-catalog.py` падает с ошибкой, если в `catalog.yaml` есть блок без обязательного поля — каталог считается невалидным целиком.
- `validate-meta.py` не находит `meta.yaml` в указанной директории — скрипт возвращает ненулевой exit-code, но не создаёт файл автоматически.
- `scaffold-block.py` создаёт блок с уже существующим `--id` — перезаписывает файлы без предупреждения, если папка присутствует.
- Блок добавлен в файловую систему, но не внесён в `catalog.yaml` — агенты downstream не видят блок при поиске по каталогу.
- Расхождение схемы `meta.yaml` между новым блоком и ожидаемой версией схемы — валидация молча пропускает неизвестные поля, если скрипт не обновлён вместе со схемой.
