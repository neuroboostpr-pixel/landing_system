# Генератор дизайн-системы (моды)

## Что делает

Снимает с РЕФЕРЕНСА клиента вид и приёмы — цвета, шрифты, размеры, объекты-роли, движение — и упаковывает их в самодостаточный мод под папкой `05_ДИЗАЙН-СИСТЕМА/moods/{mood}/`. Один референс равен одному муду. Агент читает ВСЕ экраны референса (не только hero), проходит 21-уровневый чек-лист, снимает данные ГЛАЗАМИ, измеряет цвета по пикселям через `scripts/extract-palette.py`. Структуру и тексты лендинга скилл не трогает — это зона прототипа.

## Когда вызывается

Вызывается командой `/landing-design` на этапе 05, после того как утверждены референсы (этап 03) и брендинг (этап 04). Для каждого референса из `references-index.md` запускается отдельный цикл — получается набор мудов.

## Вход → выход

**Вход:** скриншоты референсов в `03_РЕФЕРЕНСЫ/*.png`, файл `03_РЕФЕРЕНСЫ/references-index.md` с маппингом «референс → мод».

**Выход:** для каждого мода — папка `05_ДИЗАЙН-СИСТЕМА/moods/{mood}/` с файлами: `palette.css` (все цвета `--lp-*`), `typography.css` (шрифты, кегли, межстрочные), `metrics.css` (размеры-токены), `motion.css` (ease/reveal/parallax/float/glow), `objects.yaml` (роли через ссылки на токены + поле `motion`), `compositions/*.yaml` (расположение ref-роль без дублирования параметров).

## Failure modes

- **Читается только hero-экран** — roles для карточек, форм, FAQ, футера не снимаются → неполный `objects.yaml`; дефект ловится только на этапе 07c при вёрстке.
- **Hex/px вне токенов** — прямые значения в компонентных CSS/HTML вместо ссылок на токены; гейт `verify_tokens.py` возвращает FAIL.
- **Гигантский `--fs-h1`** — clamp до 7rem на длинный заголовок даёт стену текста; не помещается в первый экран desktop.
- **Различие по модам без нового токена** — размер кнопки 140px vs 118px жёстко прописан в каждом муде вместо отдельного `--cta-size`; мод «протекает».
- **Выдуманные цвета/шрифты** — агент не зумит референс и угадывает оттенок; обнаруживается только при визуальном QA.
