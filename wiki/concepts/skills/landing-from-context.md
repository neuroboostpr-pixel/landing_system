# Создание лендинга из контекста агентства

## Что делает

Создаёт новый лендинг-проект внутри родительской папки агентства, которая уже содержит исследования, данные о ЦА и черновики прототипа. Скилл делает снепшот релевантных подпапок родителя в структуру нового лендинга — копирует контекст, исследования и прототип без создания символических ссылок. После копирования лендинг становится полностью самодостаточным и независимым от родителя. Передаёт управление `landing-orchestrator`, стартуя с этапа 02, поскольку этапы 00–01 уже частично заполнены унаследованными данными.

## Когда вызывается

Вызывается командой `/landing-from-context <slug>`, когда текущая рабочая директория — папка агентства со структурой `01_контекст/`, `04_документы/`, `05_исследования/`. Типичный сценарий: маркетолог работает в родительском проекте курса или агентства и хочет создать отдельный лендинг, унаследовав накопленные материалы по целевой аудитории и прототипам.

## Вход → выход

**Вход:** slug нового лендинга; родительская папка агентства с подпапками `01_контекст/`, `04_документы/` (прототип-*.md), `05_исследования/`; опциональный флаг `--cinematic`.

**Выход:** полная структура нового лендинга в `~/Lendings/<slug>/` с заполненными `01_КОНТЕКСТ/` (скопированные исследования), `07_КОНТЕНТ/prototype.md` (из документов родителя), `01_КОНТЕКСТ/source-references.yaml` (метаданные источника). Оркестратор запускается с этапа 02.

## Failure modes

- Если родительская папка не содержит ожидаемых подпапок (`01_контекст/`, `05_исследования/`), снепшот создаётся частично или пустым — агент должен запросить у пользователя путь к прототипу вручную.
- Файл `prototype.md` не будет создан, если в `04_документы/` нет файлов с именем `прототип-*.md` — нужно уточнять у пользователя.
- Если slug уже существует в `~/Lendings/`, `init.sh` завершится с ошибкой — конфликт имён не разрешается автоматически.
- Данные копируются один раз как снепшот: последующие изменения в родительском проекте не отражаются в лендинге, что может привести к расхождению версий при долгосрочной работе.
- Логирование pre-flight (`scripts.wiki.log`) может упасть если wiki-модуль не инициализирован — не блокирует основной флоу, но ломает метрики routing.
