# landing-from-context

## Что делает

Создаёт новый лендинг-проект внутри системы, унаследовав данные из уже существующей папки агентства — аудиторию, исследования, прототип текста. Один раз скопировал нужное — дальше лендинг живёт самостоятельно.

## Когда вызывать / в каком этапе

Запускается в самом начале работы над новым лендингом, когда текущая рабочая папка — родительский проект агентства. Условия активации:

- Пользователь произносит фразу «новый лендинг по этому курсу/проекту» или явно вводит `/landing-from-context <slug>`.
- В текущей директории присутствуют подпапки `01_контекст`, `04_документы`, `05_исследования` — признаки структуры агентства.

## Что на вход / на выход

**Вход:**
- `slug` — имя нового лендинга (kebab-case).
- Родительская папка агентства со стандартной структурой подпапок.
- Опциональный флаг `--cinematic`.

**Выход:**
- Новая папка лендинга `~/Lendings/<slug>/` (создаётся через `landing-project-init`).
- Снепшоты данных родителя:
  - `01_контекст/` → `<лендинг>/01_КОНТЕКСТ/`
  - `05_исследования/` → `<лендинг>/01_КОНТЕКСТ/исследования/`
  - `04_документы/прототип-*.md` → `<лендинг>/07_КОНТЕНТ/prototype.md`
- Файл `01_КОНТЕКСТ/source-references.yaml` — фиксирует источник каждой копии.
- Управление передаётся `landing-orchestrator`, начиная с этапа 02 (этапы 00–01 уже частично заполнены).

**Что НЕ делается:** симлинки не создаются, родительский проект не изменяется, данные не угадываются — при отсутствии файлов-прототипов задаётся вопрос пользователю.

## Связанные концепты

- [[landing-project-init]] — базовый скилл инициализации: создаёт структуру папок лендинга через `init.sh`
- [[landing-orchestrator]] — принимает управление после создания проекта и ведёт через все оставшиеся этапы
- [[landing-new]] — альтернативная команда: создаёт пустой лендинг без наследования контекста
