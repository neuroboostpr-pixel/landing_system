# Landing From Context — создание лендинга из родительского проекта агентства

## Что делает

Создаёт новый лендинг-проект, унаследовав данные из уже существующей папки агентства: исследования аудитории, прототипы текстов, документы. Один раз скопировал — лендинг живёт самостоятельно.

## Когда вызывать / в каком этапе

Вызывается вручную командой `/landing-from-context <slug>`, когда текущая рабочая папка — это родительский проект агентства (структура содержит `01_контекст/`, `04_документы/`, `05_исследования/`). Используется вместо `/landing-new`, если уже есть готовые материалы о ЦА и прототип текста.

## Что на вход / на выход

**Вход:**
- `slug` — имя нового лендинга (kebab-case)
- Опционально: флаг `--cinematic`
- Родительская папка агентства с подпапками `01_контекст/`, `04_документы/`, `05_исследования/`

**Выход:**
- Новая папка лендинга `~/Lendings/<slug>/` с полной структурой из шаблона
- Скопированные данные:
  - `01_контекст/` → `<slug>/01_КОНТЕКСТ/`
  - `05_исследования/` → `<slug>/01_КОНТЕКСТ/исследования/`
  - `04_документы/прототип-*.md` → `<slug>/07_КОНТЕНТ/prototype.md`
  - `01_КОНТЕКСТ/source-references.yaml` — журнал источников копирования
- Управление передаётся `landing-orchestrator` с этапа 02 (этапы 00–01 уже частично заполнены)

## Ключевые ограничения

- Создаёт только **snapshot** (полная копия), без симлинков и без связи с родителем
- Не модифицирует данные родительского проекта
- Если прототип не найден — спрашивает пользователя, не угадывает
- Этапы 00–01 пропускаются как уже выполненные на стороне агентства

## Связанные концепты

- [[landing-project-init]] — базовый скрипт инициализации структуры нового лендинга, вызывается внутри `from-context.sh`
- [[landing-orchestrator]] — оркестратор этапов, получает управление начиная с этапа 02
- [[landing-new]] — альтернативная команда создания пустого проекта без наследования контекста
