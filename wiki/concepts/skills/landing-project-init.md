# Инициализация нового проекта лендинга

## Что делает

Создаёт чистую папку нового проекта-лендинга по шаблону системы. Принимает slug от пользователя, запрашивает базовые поля (ниша, клиент, желаемый домен), запускает `scripts/init.sh`, который разворачивает полную структуру из 13+ папок в `~/Lendings/<slug>/`. Сразу после этого открывает `00_БРИФ/brief.md` и передаёт управление `landing-orchestrator` — с этапа 00.

## Когда вызывается

Запускается командой `/landing-new <slug>` — когда пользователь хочет начать новый лендинг с нуля, без существующего контекста. Если проект создаётся из папки агентства или клиента, вместо этого скилла используется `landing-from-context`.

## Вход → выход

**Вход:** slug проекта (kebab-case строка), опционально флаг `--cinematic` для premium-режима, базовые метаданные (ниша, клиент, домен — можно отложить).

**Выход:** новая папка `~/Lendings/<slug>/` со структурой шаблона, инициализированным git-репо, заполненными placeholder-файлами в README.md и CLAUDE.md проекта; управление передано оркестратору.

## Failure modes

- Slug содержит кириллицу или пробелы — `init.sh` может создать папку с непредсказуемым именем; рекомендуется kebab-case.
- Папка `~/Lendings/<slug>/` уже существует — скрипт может перезаписать или упасть без предупреждения.
- Не установлен `git` или отсутствует доступ к директории `~/Lendings/` — инициализация репо упадёт молча.
- Шаблон `template/` повреждён или неполон — копирование создаст неполную структуру этапов без явной ошибки.
- Оркестратор не запустился после передачи управления — проект создан, но workflow не начат; пользователь не получит подсказки о следующем шаге.
