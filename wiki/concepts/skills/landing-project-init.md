# landing-project-init — Создание нового проекта лендинга

## Что делает
Создаёт чистую папку нового лендинг-проекта по шаблону: копирует структуру директорий, инициализирует git-репозиторий и передаёт управление оркестратору для прохождения полного workflow.

## Когда вызывать / в каком этапе
Вызывается в самом начале работы над новым лендингом — до любых этапов (00–12). Активируется командой `/landing-new <slug>` или когда пользователь явно просит «создать новый лендинг с нуля». Не подходит, если проект уже существует в виде клиентской папки агентства — для этого используется `landing-from-context`.

## Что на вход / на выход

**На вход:**
- `slug` — имя проекта в kebab-case (обязательно)
- `--cinematic` — необязательный флаг premium-режима
- Базовые поля, которые скилл запрашивает интерактивно: ниша, клиент, желаемый домен (домен можно пропустить)

**На выход:**
- Папка `~/Lendings/<slug>/` со структурой из `template/` (13+ подпапок, 00–12)
- Инициализированный git-репозиторий проекта
- Заполненные placeholder'ы в `README.md` и `CLAUDE.md` проекта
- Открытый файл `00_БРИФ/brief.md` для заполнения первого этапа
- Управление передаётся `landing-orchestrator` — он ведёт workflow с этапа 00

## Ограничения
Скилл **не** создаёт WordPress-сайт (это делается на этапе 09 через `wp-deployer`), не требует домена жёстко на старте, не вызывает никаких агентов кроме `landing-orchestrator`. Папка проекта создаётся **вне** мастер-системы `landing-system/` — намеренно, чтобы не смешивать системные файлы и клиентские данные.

## Связанные концепты
- [[landing-orchestrator]] — получает управление после инициализации и ведёт проект через все 12 этапов
- [[landing-from-context]] — альтернативный путь создания проекта из уже существующей папки клиента/агентства
- [[landing-start]] — onboarding-wizard для новичков, вызывает этот скилл внутри своего flow
