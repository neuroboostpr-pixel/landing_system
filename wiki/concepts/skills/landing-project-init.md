# Инициализация нового проекта лендинга

## Что делает

Создаёт чистую папку нового лендинг-проекта с нуля. Принимает kebab-case slug, запрашивает базовые поля (ниша, клиент, домен — опционально), запускает `scripts/init.sh`, который копирует структуру `template/` в `~/Lendings/<slug>/`, инициализирует git-репозиторий и подставляет плейсхолдеры в README.md и CLAUDE.md проекта. По завершении открывает `00_БРИФ/brief.md` для заполнения и передаёт управление `landing-orchestrator` с этапа 00.

## Когда вызывается

Вызывается командой `/landing-new <slug>` или когда пользователь явно просит «создать новый лендинг» с нуля. Используется опытными пользователями, которым не нужен интерактивный wizard. Для новичков предназначен `/landing-start` (PR-E wizard). Для создания проекта из существующего контекста агентства — `landing-from-context`.

## Вход → выход

**Вход:** slug проекта (kebab-case), опционально — ниша, имя клиента, целевой домен. Требует работающего `scripts/init.sh` и наличия `template/` в мастер-системе.

**Выход:** папка `~/Lendings/<slug>/` с полной структурой 13 подпапок (этапы 00–12), инициализированный git-репозиторий, заполненный `00_БРИФ/brief.md` готов к работе, `landing-orchestrator` запущен на этапе 00.

## Failure modes

- **Slug содержит пробелы или кириллицу** — `init.sh` может создать папку с некорректным именем; рекомендован строгий kebab-case до передачи в скрипт.
- **`template/` отсутствует или повреждён** — скрипт упадёт без информативного сообщения; нужна проверка перед вызовом.
- **Папка уже существует** — `init.sh` перезапишет содержимое без предупреждения, что уничтожит существующий прогресс.
- **`landing-orchestrator` не запустился** — проект создан, но workflow не начат; пользователь может не заметить и остаться без следующего шага.
- **Не установлены зависимости** — `scripts/check-deps.sh` не вызывается автоматически; скил не проверяет наличие git, bash, Python перед запуском.
