# Landing Project Init — создание нового проекта лендинга

## Что делает
Создаёт чистую папку нового лендинг-проекта из шаблона системы: копирует структуру директорий, инициализирует git-репозиторий и передаёт управление оркестратору для старта workflow.

## Когда вызывать / в каком этапе
Вызывается в самом начале — когда пользователь хочет запустить **новый** проект с нуля. Триггеры: команда `/landing-new <slug>`, фраза «создай новый лендинг» или любой эквивалент. Если проект уже существует в виде контекста агентства — использовать `landing-from-context` вместо этого скилла.

## Что на вход / на выход

**Вход:**
- `<slug>` — имя проекта в kebab-case (например, `lp-kurs-marafon`)
- Опционально: `--cinematic` — флаг premium-режима
- Базовые поля от пользователя: ниша, имя клиента, желаемый домен (домен можно отложить)

**Выход:**
- Папка `~/Lendings/<slug>/` со структурой из `template/` (18 подпапок, этапы 00–12)
- Инициализированный git-репозиторий проекта
- Заполненные placeholder'ы в `README.md` и `CLAUDE.md` проекта
- Открытый файл `00_БРИФ/brief.md` для заполнения первого этапа
- Передача управления `landing-orchestrator` с этапа 00

## Связанные концепты
- [[landing-orchestrator]] — получает управление после инициализации, ведёт проект через все 12+ этапов
- [[landing-from-context]] — альтернатива когда проект создаётся из существующего агентского контекста, а не с нуля
- [[landing-start]] — onboarding-wizard для новичков, вызывает этот скилл внутри
- [[scripts/init.sh]] — bash-скрипт, выполняющий фактическое копирование шаблона и git init
