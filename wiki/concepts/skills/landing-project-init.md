# landing-project-init — Инициализация нового проекта лендинга

## Что делает
Создаёт чистую папку нового проекта лендинга по шаблону и запускает workflow с нулевого этапа. Это стартовая точка для проектов «с нуля» — не из существующего контекста агентства.

## Когда вызывать / в каком этапе
Вызывается при команде `/landing-new <slug>` или когда пользователь говорит «создай новый лендинг». Подходит только для чистого старта — если проект уже существует в контексте агентства, используй [[landing-from-context]].

## Что на вход / на выход

**Вход:**
- `<slug>` — имя проекта в kebab-case (например, `lp-курс-марафон`)
- Опционально: ниша, клиент, домен
- Флаг `--cinematic` для premium-режима

**Выход:**
- Папка `~/Lendings/<slug>/` со структурой из `template/` (13 подпапок)
- Инициализированный git-репозиторий проекта
- Заполненные placeholder в `README.md` и `CLAUDE.md` проекта
- Открытый `00_БРИФ/brief.md` для первого этапа

**Побочные эффекты:**
- Папка проекта создаётся вне `landing-system/` — она не вкладывается в мастер-систему
- После создания скилл передаёт управление агенту [[landing-orchestrator]] с этапа 00

## Как работает (шаги)
1. Принимает slug проекта
2. Запрашивает базовые поля: ниша, клиент, домен (опционально)
3. Запускает `scripts/init.sh <slug>` — копирует `template/`, инит git, подставляет плейсхолдеры
4. Открывает `00_БРИФ/brief.md` для заполнения
5. Передаёт управление `landing-orchestrator` на этап 00

## Что НЕ делает
- Не создаёт WordPress (это этап 09, [[wp-deployer]])
- Не требует домен жёстко — его можно указать на этапе 09
- Не вызывает других агентов, кроме передачи `landing-orchestrator`

## Связанные концепты
- [[landing-from-context]] — альтернатива: создать проект из родительской папки агентства
- [[landing-orchestrator]] — принимает управление после инициализации и ведёт workflow через 12 этапов
- [[wp-deployer]] — финальный этап: деплой WordPress на Бегет
