# Frontend Builder — CSS и block.php по wireframes

## Что делает

Агент берёт wireframe-описания из DESIGN.md §5 и превращает их в production-код: для каждого блока пишет фenced CSS-секцию прямо в §5 и полностью перезаписывает соответствующий `block.php` в теме WordPress. Работает на этапе 08b, после того как `/landing-build` создал скелеты блоков. Генерирует только визуальный слой — нулевой JavaScript, BEM-классы, CSS-переменные из токенов §2, медиа-запросы из §3.3. После прохода всех блоков вызывается `extract-main-css.py`, который собирает итоговый `main.css`.

## Когда вызывается

Вызывается командой `/landing-style` после завершения `/landing-build`. Перед стартом проверяет, что `.landing-state.yaml` содержит `current_stage == 08_build` и что gate-check для этапа 08 прошёл без ошибок. Если предшественник не закрыт, harness-хук физически блокирует запись файлов.

## Вход → выход

**Вход:** `DESIGN.md` (только §5 — wireframes, элементы, BEM-классы, поведение), `block-spec.yaml` (список блоков, контролы, BEM-корень), скелеты `block.php` (read-only, только для ориентации), `brand-kit.md` и `landing-structure.md` (контекст).

**Выход:** в `DESIGN.md §5` — добавлен fenced-блок ` ```css ` после `**CSS rules:**` для каждого блока; `block.php` каждого блока полностью перезаписан с маркером `// AUTO-GENERATED by frontend-builder.` и разметкой по wireframe.

## Failure modes

- **Отсутствие токена** — если нужный `var(--token)` не описан в §2, агент оставляет `/* TODO: missing token */` и продолжает с CSS-fallback; итоговый main.css может содержать неразрешённые ссылки.
- **Ложный exit-1 gate** — `check-block-php-markers.py` считает sub-block.php (repeater-children) без маркера ошибкой; это known false positive, не блокирует продакшн.
- **Изобретённые layout-хелперы** — если §5 не описывает адаптив, агент fallback'ит на single-column stack; при неверном wireframe результат может не совпасть с ожиданиями дизайнера.
- **Перезапись вручную правленных block.php** — маркерный заголовок сигнализирует, что файл авто-генерирован; ручные правки будут потеряны при повторном прогоне.
- **Порядок секций в DESIGN.md** — если §5 расположен не по числовому порядку, CSS-экстрактор соберёт каскад с багами; агент не проверяет порядок, только добавляет в нужный раздел.
