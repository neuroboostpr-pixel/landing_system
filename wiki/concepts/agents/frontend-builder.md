# frontend-builder — Агент генерации CSS и шаблонов блоков

## Что делает

Переводит текстовые вайрфреймы из DESIGN.md §5 в реальный продакшн-CSS и PHP-шаблоны блоков Lazy Blocks. Берёт описания блоков — и выдаёт готовый визуальный код для WordPress-темы.

## Когда вызывать / в каком этапе

Этап **08b** (стиль), запускается после `/landing-build` (этап 08). Вызывается slash-командой `/landing-style`. Работает только если `current_stage == 08_build` в `.landing-state.yaml`. Перед любым действием агент читает state-файл, рендерит Mermaid-карту пайплайна через `render-pipeline-map.sh` и прогоняет `gate-check.sh`.

## Что на вход / на выход

**Входные артефакты (только чтение):**
- `05_ДИЗАЙН-СИСТЕМА/DESIGN.md` — вайрфреймы §5, токены §2, брейкпоинты §3.3, motion §7, a11y §8
- `04_БРЕНД/brand-kit.md` — брендинг
- `08_КОД/block-spec.yaml` — список блоков, BEM-классы, контролы
- `08_КОД/wp-theme/blocks/lazyblock-<slug>/block.php` — текущие скелеты (справка)

**Выходные артефакты (агент пишет):**
- **DESIGN.md §5** — в каждый раздел `### Block N` добавляется fenced ` ```css ` блок под заголовком `**CSS rules:**`. Существующие инвентарные строки `**CSS:** .class1, ...` не трогаются.
- **`lazyblock-<slug>/block.php`** — полная перезапись каждого файла с маркером `// AUTO-GENERATED by frontend-builder.` в заголовке.

После завершения slash-команда запускает `extract-main-css.py`, который регенерирует `main.css` из обновлённого DESIGN.md.

**Что агент НЕ трогает:** DESIGN.md §1–§4 и §6–§9, `block-spec.yaml`, `style.css`, `functions.php`, `assets/js/*`, `page-content.html`, `tokens.json`, `brand-kit.md`.

**Ключевые правила:**
- Только `var(--token)` — никаких хардкод-цветов или размеров
- Брейкпоинты в `@media` — только литеральный px из §3.2 (не `var(--bp-*)`)
- Ноль JS — аккордеоны через `<details>`, sticky CTA через CSS
- Допускается один layout-helper BEM-класс на блок если вайрфрейм требует обёртки
- При флаге `--block <slug>` обрабатывается только один блок

**Известное ограничение:** дочерние `block.php` файлов Lazy Blocks (repeater-паттерны — `lazyblock-faq-item`, `lazyblock-reviews-item` и др.) генерируются `generate-lzb-templates.py`, не этим агентом. `check-block-php-markers.py` может ложно сигнализировать об отсутствии маркера в них — это known false positive.
