# Icon Generator — генератор одной иконки PNG

## Что делает
Генерирует один PNG-файл иконки для конкретного слота лендинга через codex image_gen. Перед генерацией проверяет хеш-кеш — если иконка с такими же параметрами уже создавалась, берёт её из кеша без повторного вызова API.

## Когда вызывать / в каком этапе
Вызывается **только родительским агентом** `visual-curator` на этапе **07d (визуалы)**. Прямой вызов пользователем не предусмотрен — `icon-generator` является вспомогательным (helper) агентом. Stage Execution Protocol контролируется родителем.

## Что на вход / на выход

**Вход:**
- `<project_dir>` — абсолютный путь к папке проекта
- `<slot_name>` — имя слота иконки (например, `feature-1-icon`)
- `<hint>` — опциональная подсказка для генерации (например, `shield`)

**Выход:**
- `<project>/07d_VISUALS/icons/<slot_name>.png` — готовый PNG-файл иконки

## Процесс работы

1. **Вычисление кеш-ключа** — запускается `visual-cache.py` с параметрами: hint, icon_style, brand_color, niche. Ключ — хеш всех четырёх значений.
2. **Проверка кеша** — если файл `.cache/<hash>.png` существует и весит ≥ 1 КБ, он копируется в целевую папку без вызова codex.
3. **Генерация** — если кеша нет, запускается `codex-generate-icon.sh`.
4. **Сохранение в кеш** — успешный результат копируется в `.cache/<hash>.png` для повторного использования.

**Обработка ошибок:**
- Если codex упал после повторных попыток — создаётся SVG-заглушка через `svg-placeholder.py` (тот же скрипт, что использует PR-B).
- При проблемах с хрома-кей — повторная попытка с флагом `--edge-contract 1` или альтернативным цветом `#ff00ff`.

## Связанные концепты
- [[visual-curator]] — родительский агент, который диспатчит icon-generator для каждого слота на этапе 07d
- [[visual-cache]] — скрипт хеширования и кеша, предотвращает повторные вызовы codex
- [[codex-generate-icon]] — bash-скрипт, непосредственно вызывающий codex image_gen
- [[svg-placeholder]] — fallback-генератор SVG-заглушек при ошибке codex (из PR-B)
