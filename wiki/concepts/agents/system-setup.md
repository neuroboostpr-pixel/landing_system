# System Setup — Настройщик системы

## Что делает

Запускается один раз при первом знакомстве с системой: проверяет окружение, настраивает файл `.env` с ключами, заполняет `config/system.yaml` (CRM, аналитика, JS-библиотеки). После завершения — система готова создавать лендинги.

## Когда вызывать / в каком этапе

Вызывается вручную командой `/landing-setup` перед любой работой с системой. Это не часть конвейера этапов — запускается ровно один раз на новой машине или при свежей установке. Stage Execution Protocol к нему **не применяется**.

## Что на вход / на выход

**Вход:**
- Ответы пользователя на интерактивные вопросы (CRM, Telegram-бот, аналитика, JS-библиотеки)
- Опциональный `.env.example` и `config/system.yaml.template` как шаблоны

**Выход:**
- `.env` — заполненный файл с секретами (`FIRECRAWL_API_KEY`, `BEGET_USER`, `BEGET_HOST`, `BEGET_PATH`, токены интеграций)
- `config/system.yaml` — флаги и публичные настройки (CRM-провайдер, GTM, Метрика, JS-библиотеки, попапы)
- Текстовый отчёт в терминале: что подключено, что пропущено

**Правило безопасности:** токены и API-ключи — только в `.env`. В `system.yaml` хранятся исключительно флаги (`enabled: true`) и публичные значения (поддомен CRM).

## Шаги работы

1. **Preflight** — запускает `scripts/preflight.sh`. При ошибках (`❌`) объясняет причину и ждёт исправления, затем повторяет проверку.
2. **Настройка .env** — если файл отсутствует, копирует из `.env.example` и поочерёдно спрашивает каждое пустое поле. Объясняет, где получить ключ (например, `FIRECRAWL_API_KEY` — на firecrawl.dev).
3. **Заполнение config/system.yaml** — интерактивный опрос по 6 темам: CRM, Telegram, Метрика, GTM, JS-библиотеки, попапы.
4. **Финальный отчёт** — показывает сводку подключённых сервисов и подсказку `/landing-new <slug>`.
