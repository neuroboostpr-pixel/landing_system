# QA-аудитор

## Что делает

Проверяет 7 базовых критериев качества задеплоенного лендинга: доступность сайта, редирект HTTP→HTTPS, наличие мета-тегов (title, description, og:title), подключение Яндекс Метрики и GTM, рендер формы Fluent Forms и наличие viewport-мета для мобайла. По результатам формирует отчёт `10_QA/qa-report.md` и ждёт явного утверждения от пользователя — без него этап не закрывается.

## Когда вызывается

Запускается на этапе 10 после завершения деплоя (`/landing-deploy`, этап 09). Оркестратор диспатчит агента, когда `.landing-state.yaml` показывает `current_stage == 10_qa` и этап 09 отмечен как `approved`.

## Вход → выход

**Вход:** URL сайта из `00_БРИФ/brief.md`; живой задеплоенный сайт доступен по сети.

**Выход:** `10_QA/qa-report.md` — таблица из 7 строк с результатами ✅/❌ по каждому критерию; статус этапа `10_qa` переводится в `approved` через `gate-state.sh` только после того, как пользователь явно подтвердил отчёт.

## Чем закрывается этап (gates)

- `qa_report_approved` — пользователь посмотрел отчёт и явно дал approve; агент не закрывает этап автоматически

## Failure modes

- **Сайт не отвечает** — curl возвращает не 200; агент фиксирует ❌, этап не закрыть без правки деплоя.
- **HTTPS не настроен** — 301-редирект с http → https отсутствует; частая проблема после первого деплоя на Бегет.
- **Счётчики не грузятся** — код Яндекс Метрики или GTM не найден в HTML; нужно проверять functions.php темы.
- **Fluent Forms не рендерится** — shortcode `[fluentform]` есть в базе, но плагин деактивирован или не установлен.
- **Предшественник не закрыт** — harness-хук `enforce_stage_gate.py` блокирует Write-доступ, если этап 09 не `approved`; не обходить, идти закрывать 09.
