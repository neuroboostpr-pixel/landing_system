# Стилист фотографий

## Что делает

Обрабатывает сырые клиентские фотографии для использования в лендинге: вырезает фон, чистит края, накладывает лёгкий композитинг (тени, текстуры), кадрирует под нужные слоты, конвертирует форматы. Работает строго через скрипт `style.py` из skill `photo-styling` — никакого прямого использования PIL, сторонних API или кастомных обходов. Если `HUGGINGFACE_TOKEN` не задан, переходит в режим генерации промптов для ручной обработки в ChatGPT или Шедевруме.

## Когда вызывается

Вызывается родительским агентом `photo-curator` в рамках этапа 07c (Photo Pipeline). Прямой запуск пользователем не предполагается. Предусловие: в папке `02_МАТЕРИАЛЫ_КЛИЕНТА/photos/original/` должны лежать исходные фото клиента.

## Вход → выход

**Вход:** исходные фото клиента в `02_МАТЕРИАЛЫ_КЛИЕНТА/photos/original/`; `brand-kit.md` для режима генерации промптов; статус переменной `HUGGINGFACE_TOKEN`.

**Выход:** обработанные фото в `02_МАТЕРИАЛЫ_КЛИЕНТА/photos/processed/`; обновлённый `stylesheet.md` с описанием применённых правил; либо `photo-prompts.md` с готовыми промптами для ручной обработки (в fallback-режиме).

## Failure modes

- `HUGGINGFACE_TOKEN` не задан, но агент пытается запустить `style.py` — нужно сначала проверить токен и уйти в fallback.
- Использование стороннего инструмента вместо `style.py` нарушает архитектурный контракт и делает запреты из «Forbidden» неисполнимыми.
- Путаница со стадией: агент указывает пути к `02_МАТЕРИАЛЫ_КЛИЕНТА`, хотя логируется на `--stage 07c` — при рефакторинге путей важно проверить соответствие.
- HARD GATE (просмотр `assets-gallery.html`) не пройден — переход на следующий этап заблокирован, но агент сам об этом не предупредит без родителя.
- Fallback-промпты сгенерированы, пользователь добавил обработанные фото вручную, но не перезапустил `/landing-photos` — `photo-curator` не получит обновлённый инвентарь.
