# Классификатор фотографий

## Что делает

Обрабатывает одну фотографию из папки `07c_PHOTOS/intake/` со статусом `tag_source: pending_ai_classify` и получает её машинные метаданные через Codex CLI. По итогу работы в `catalog.yaml` появляется запись с тегами, подписью, описанием композиции, поддерживаемыми соотношениями сторон, признаком совместимости с брендом и примечаниями. Агент — вспомогательный: он не владеет этапом и запускается только внутри `photo-curator`. Identity-safe: фото не изменяется, агент работает исключительно в режиме чтения.

## Когда вызывается

Вызывается родительским агентом `photo-curator` для каждой фотографии с флагом `pending_ai_classify`. Прямой вызов пользователем не предусмотрен.

## Вход → выход

**Вход:** абсолютный путь к папке проекта `<project_dir>` и путь к конкретному фото `<photo_path>`; контекст проекта (`tokens.json`, `market-profile.md`) для формирования промпта.

**Выход:** запись в `<project>/07c_PHOTOS/catalog.yaml` (добавляется или обновляется по полю `id`) со статусом `tag_source: ai_classify`; полный лог промпта и ответа сохраняется в `07c_PHOTOS/.logs/`.

## Failure modes

- Codex возвращает невалидный YAML — агент делает два повтора со строгим промптом; если оба не помогают, помечает фото как `unclassified` и записывает предупреждение в `STATE.yaml`.
- Codex «молча» завершается с ошибкой — обрабатывается обёрткой `call-codex.sh` (повтор + ненулевой exit code).
- Отсутствует `tokens.json` или `market-profile.md` — рендер промпта упадёт до вызова Codex; родительский агент должен убедиться, что этапы 05 и 07a закрыты до запуска классификации.
- Файл `catalog.yaml` заблокирован параллельной записью — при одновременном запуске нескольких экземпляров возможна гонка; `photo-curator` должен сериализовать вызовы.
- Неожиданный формат ответа Codex (лишние поля/HTML-обёртка) — парсер может не найти нужные ключи; нужна валидация схемы перед записью.
