# Lifecycle Keeper — Хранитель версий

## Что делает

Системный агент вне основного пайплайна: создаёт версионные снапшоты лендинга, откатывает тему к любой из сохранённых версий и клонирует проект для A/B-тестирования. Работает исключительно с файловой системой и bash-скриптами из скилла `landing-versioning-and-cloning`. Stage Execution Protocol к нему не применяется — у агента нет «своего» этапа.

## Когда вызывается

Вызывается вручную через слеш-команды `/landing-rollback` и `/landing-clone`. Откат нужен, когда после деплоя что-то сломалось и надо быстро вернуть рабочую версию. Клон — когда требуется A/B-вариант лендинга на отдельном поддомене.

## Вход → выход

**Вход:** директория проекта (путь) и метка версии (например `v1.0`) для снапшота; или путь проекта + новый slug для клонирования.

**Выход:**
- Снапшот: сохранённая директория `09_ВЕРСИИ/<tag>/`.
- Откат: перезаписанная `08_КОД/wp-theme` из выбранного снапшота + запуск `/landing-deploy`.
- Клон: полная копия проекта в `~/Lendings/<new-slug>/`, готовая к деплою на новый поддомен.

## Failure modes

- **Снапшот отсутствует** — откат невозможен; агент сообщит, что `09_ВЕРСИИ/` пустая; нужно создавать версию до деплоя.
- **Конфликт slug при клонировании** — если папка `~/Lendings/<new-slug>` уже существует, скрипт `clone-landing.sh` может перезаписать данные; требуется проверять наличие директории вручную.
- **Деплой после отката не запущен** — откат только перезаписывает локальные файлы; без повторного `/landing-deploy` изменения не попадут на сервер.
- **Частичный снапшот** — если `create-version.sh` прервался, в `09_ВЕРСИИ/<tag>/` может быть неполный набор файлов; откат к такой версии сломает тему.
- **Нет прав на SSH/Бегет** — при клоне на новый поддомен деплой упадёт, если `.env` не настроен для нового сайта.
