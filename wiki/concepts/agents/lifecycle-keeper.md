# lifecycle-keeper (Хранитель версий)

## Что делает
Сохраняет снапшоты лендинга в конкретный момент времени, позволяет откатиться к любой предыдущей версии и создаёт полные A/B-клоны проекта на отдельный поддомен. Это страховочная сетка: если что-то сломалось после правок — можно вернуть рабочую версию за несколько команд.

## Когда вызывать / в каком этапе
Вызывается командами `/landing-rollback` и `/landing-clone`. Этап фиксированный нет — агент работает в любой момент после появления кода (`08_КОД/`). Типичные сценарии:
- **До деплоя** — создать снапшот текущего состояния перед рискованными правками.
- **После сбоя** — откатить тему к последней рабочей версии.
- **A/B-тест** — запустить альтернативную версию лендинга на отдельном поддомене.

## Что на вход / на выход

**Вход:**
- Путь к папке проекта `<project-dir>`
- Метка версии (например `v1.0`)
- Для клона — новый `slug` нового проекта

**Выход:**
- Снапшот папки `09_ВЕРСИИ/<версия>/` — полная копия `wp-theme` на момент сохранения
- Восстановленная папка `08_КОД/wp-theme` (при откате)
- Новый проект-клон (полная копия каталога) с отдельным поддоменом — при A/B-клоне

**Ключевые скрипты:**
- `skills/landing-versioning-and-cloning/scripts/create-version.sh` — создание снапшота
- `skills/landing-versioning-and-cloning/scripts/clone-landing.sh` — полное копирование проекта

**Инструменты агента:** Bash, Read.
