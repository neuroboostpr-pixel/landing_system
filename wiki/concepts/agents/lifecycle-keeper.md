# Хранитель версий (lifecycle-keeper)

## Что делает

Отвечает за операции жизненного цикла лендинга вне основного пайплайна: создаёт снапшоты проекта (версии), откатывает код к предыдущему состоянию и клонирует проект для A/B-тестирования. Работает напрямую с файловой системой проекта и вызывает bash-скрипты из скилла `landing-versioning-and-cloning`. Этап Execution Protocol на него не распространяется — это сервисный агент уровня ops.

## Когда вызывается

Запускается командами `/landing-rollback` (откат к сохранённой версии) и `/landing-clone` (создание A/B-копии проекта). Не встроен в автоматический пайплайн оркестратора и не имеет привязки к конкретному этапу производства.

## Вход → выход

**Вход:** путь до папки проекта (`<project-dir>`), метка версии (например, `v1.0`) или слаг нового клона (`<new-slug>`). Для отката — наличие папки `09_ВЕРСИИ/` с ранее сохранёнными снапшотами.

**Выход:**
- При создании версии — снапшот в `09_ВЕРСИИ/v1.0/` (каталог с wp-theme и артефактами).
- При откате — восстановленный `08_КОД/wp-theme` из снапшота + запущенный `/landing-deploy`.
- При клонировании — новая полная копия проекта, задеплоенная на отдельный поддомен.

## Failure modes

- **Отсутствует папка `09_ВЕРСИИ/`** — откат невозможен, если предыдущие снапшоты не создавались; агент не может сам их восстановить.
- **Конфликт slug при клоне** — если проект с указанным `<new-slug>` уже существует, `clone-landing.sh` может перезаписать данные.
- **Деплой после отката падает** — откат восстанавливает код, но не конфигурацию сервера или базы данных; несоответствие схемы может сломать сайт.
- **Потеря актуального состояния** — снапшот фиксирует только `wp-theme`; медиафайлы, настройки плагинов и записи БД не версионируются.
- **Отсутствие `.landing-state.yaml` у клона** — клон наследует yaml родителя; если его не обновить вручную, оркестратор будет читать неверный статус.
