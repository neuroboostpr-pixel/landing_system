# Онбординг-визард нового проекта

## Что делает

Интерактивный гид для маркетолога при старте нового лендинга. Объясняет систему в трёх коротких параграфах, создаёт папку проекта через скилл `landing-project-init`, а затем поэтапно ведёт пользователя через сбор четырёх категорий материалов: прототип (обязателен), клиентские фото, логотип и референсы. После каждого шага верифицирует наличие файлов через `wizard-check-materials.py`. Завершается подсказкой запустить `/landing-go`.

## Когда вызывается

Запускается командой `/landing-start`. Предназначен исключительно для новых проектов — не трогает существующие папки и не продолжает прерванный онбординг. Вызывается вручную маркетологом или клиентом в самом начале работы над лендингом, до запуска оркестратора.

## Вход → выход

**Вход:** slug проекта (kebab-case, вводится пользователем в диалоге); файлы материалов, которые пользователь кладёт в нужные папки по запросу визарда.

**Выход:** директория `~/Lendings/<slug>/` с 18 подпапками и README-файлами; разложенные по правильным местам материалы (прототип, фото, логотип, референсы); проверенный статус каждого шага. После финала — готовность к запуску `/landing-go`.

## Failure modes

- Пользователь пишет «пропустить» на шаге с прототипом — визард отказывает, шаг повторяется, так как прототип обязателен.
- Slug уже занят (`~/Lendings/<slug>/` существует) — визард спрашивает: использовать или переименовать; новая папка поверх не создаётся автоматически.
- `wizard-check-materials.py` возвращает `fail` — шаг повторяется; возвращает `warn` — пользователь подтверждает продолжение.
- `scripts/install-codex.sh` не установлен — pre-flight падает, визард выводит инструкцию по установке и останавливается до её выполнения.
- Запуск вне landing-system repo (нет папки `template/`) — pre-flight выдаёт ошибку и не идёт дальше.
