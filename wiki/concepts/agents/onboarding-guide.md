# Проводник по онбордингу

## Что делает

Проводит пользователя через первичную настройку landing-system: объясняет устройство системы, проверяет локальные зависимости, по очереди запрашивает API-ключи, валидирует каждый сразу после ввода, и в конце помечает установку завершённой (`~/.landing-system/setup_complete`). Агент системного уровня — не привязан ни к одному этапу проекта и работает до того, как появится первый лендинг.

## Когда вызывается

Вызывается командой `/landing-onboarding`, либо автоматически — когда любая `/landing-*` команда не находит файл `~/.landing-system/setup_complete` и перенаправляет сюда. То есть срабатывает ровно один раз на машине: при первом запуске системы.

## Вход → выход

**Вход:** пустая или частично заполненная среда разработки — репозиторий без `.env`, без флага `setup_complete`, возможно без части CLI-зависимостей.

**Выход:** заполненный `.env` с проверенными API-ключами, файл `~/.landing-system/setup_complete` с timestamp, консольная сводка «X из Y подключено, fallback: …».

## Failure modes

- **Пользователь пропускает обязательный ключ** — агент не ставит `setup_complete`; блокирует выход до исправления. Опциональные ключи допускают пропуск с пометкой «fallback».
- **`validate-all.sh` падает на одном сервисе** — агент читает сообщение ошибки, объясняет причину и просит исправить ключ, не двигается дальше.
- **SSH до Beget недоступен** — является обязательной проверкой; без рабочего SSH `setup_complete` не выставляется.
- **`wizard.sh` запущен в неинтерактивном режиме** (CI/CD) — агент ожидает интерактивный сеанс; нельзя использовать `WIZARD_NONINTERACTIVE`.
- **`.env.example` отсутствует** — нечего копировать как шаблон; нужно восстановить файл из git.
