# Onboarding Guide — Проводник по первичной настройке

## Что делает

Проводит пользователя через первичную настройку landing-system: объясняет систему, проверяет зависимости, помогает заполнить API-ключи в `.env` и валидирует каждый из них сразу после ввода. В финале выставляет флаг `setup_complete`.

## Когда вызывать / в каком этапе

Активируется при двух сценариях:
1. Пользователь явно запускает команду `/landing-onboarding`.
2. Любая `/landing-*` команда обнаруживает отсутствие файла `~/.landing-system/setup_complete` и автоматически перенаправляет сюда.

Это всегда **нулевой этап** — ничего нельзя строить, пока онбординг не завершён.

## Что на вход / на выход

**Вход:**
- Отсутствие `~/.landing-system/setup_complete` (триггер)
- Файл `.env.example` в корне репозитория
- `docs/SETUP.md` — документация по настройке
- `scripts/wizard.sh` — интерактивный мастер
- `scripts/validate-all.sh` — валидатор API

**Выход:**
- `~/.landing-system/setup_complete` — файл-флаг с timestamp (создаётся только при успехе всех обязательных проверок)
- `.env` в корне репо — заполнен ключами
- Консольная сводка: «X из Y подключено, fallback: ...»

## Как работает (по шагам)

1. Читает `docs/SETUP.md`, объясняет пользователю ключевые разделы.
2. Запускает `bash scripts/wizard.sh` интерактивно.
3. При недостающих зависимостях — даёт точные команды установки, ждёт подтверждения.
4. Если `.env` отсутствует — копирует из `.env.example`, затем по очереди открывает каждую секцию: объясняет сервис, даёт ссылку на регистрацию, просит вставить ключ.
5. **После каждого ключа** немедленно запускает `bash scripts/validate-all.sh --service <name>`.
6. При ошибке валидации — читает сообщение, объясняет причину, просит исправить.
7. После успеха всех **обязательных** проверок — запускает `bash scripts/setup-flag.sh mark_complete`.

## Обязательные vs опциональные ключи

**Блокируют завершение:** `FIRECRAWL_API_KEY`, один из стоковых фото API (`PEXELS` / `UNSPLASH` / `PIXABAY`), `YM_COUNTER_ID`, `TG_BOT_TOKEN` + `TG_CHAT_ID`, один из CRM (`AMOCRM` / `BITRIX24`), `BEGET_USER` + `BEGET_HOST` + SSH-доступ.

**Опциональные (warning, не блокируют):** HuggingFace, WhatTheFont, Yandex OAuth, GTM, Cloudflare, Reg.ru — отмечаются как «fallback» в итоговой сводке.
