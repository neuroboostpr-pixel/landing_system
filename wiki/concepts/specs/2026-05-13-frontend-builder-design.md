# Frontend-builder — визуальный сборщик блоков

## Что делает

Переводит wireframe-описания из DESIGN.md §5 в реальный CSS и HTML-шаблоны: добавляет per-block стили в DESIGN.md и полностью переписывает каждый `block.php` Lazy Blocks, чтобы лендинг выглядел именно так, как нарисовано в макете — с правильными сетками, аккордеонами, бейджами и адаптивом.

## Когда вызывать / в каком этапе

Вызывается командой `/landing-style` **после** успешного прохода `/landing-build`. Gate: `.landing-state.yaml` должен иметь `stage "build" = approved`, DESIGN.md §5 непустой, `block-spec.yaml` существует, скелеты `block.php` сгенерированы. После завершения требует ручного подтверждения визуала менеджером (`style: approved`), после чего можно запускать `/landing-qa` и `/landing-deploy`.

```
/landing-build → GATE → /landing-style → GATE (manual visual) → /landing-qa → /landing-deploy
```

Флаг `--block <slug>` позволяет перегенерировать один блок без полного прогона.

## Что на вход / на выход

**Входные артефакты (read-only):**
- `05_ДИЗАЙН-СИСТЕМА/DESIGN.md` — wireframes §5, токены §2, layout, motion, a11y
- `04_БРЕНД/brand-kit.md` — контекст бренда
- `01a_АНАЛИЗ_НИШИ/landing-structure.md` — список блоков
- `08_КОД/block-spec.yaml` — блоки, controls, BEM-классы
- `08_КОД/wp-theme/blocks/lazyblock-<slug>/block.php` — скелеты как референс

**Выходные артефакты:**
- `05_ДИЗАЙН-СИСТЕМА/DESIGN.md` §5 — дополнен fenced ```css секциями для каждого блока
- `08_КОД/wp-theme/blocks/lazyblock-<slug>/block.php` — переписан с marker-шапкой `// AUTO-GENERATED by frontend-builder`
- `08_КОД/wp-theme/assets/css/main.css` — перегенерирован скриптом `extract-rules-to-main-css.py`

**Не трогает:** DESIGN.md §1-§4 и §6-§9, `block-spec.yaml`, `style.css`, `functions.php`, `page-content.html`, JS-файлы.
