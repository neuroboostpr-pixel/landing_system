# landing-start — Интерактивный wizard для новичков

## Что делает

Главная точка входа для маркетолога, который впервые встречается с landing-system. Объясняет систему за 2 минуты, создаёт папку проекта и пошагово провожает через размещение 4 типов материалов: прототип, фото, логотип, референсы.

## Когда вызывать / в каком этапе

Вызывается вручную командой `/landing-start` **до** запуска `/landing-go`. Это нулевой этап (pre-pipeline): до анализа ниши, до бренда, до любой автоматики. Без прохождения wizard нет гарантии что материалы лежат в нужных папках.

## Что на вход / на выход

**На вход:**
- Интерактивный ввод: имя проекта (kebab-case)
- Файлы от пользователя: `prototype.pdf` (обязательно), фото клиента, `logo.png/svg`, скриншоты референсов (опционально)

**На выход:**
- Папка `~/Lendings/<slug>/` — 18 директорий с русскими READMEs в каждой
- `04_БРЕНД/logos/` — новая директория для логотипов (добавлена в template PR-E)
- Верификационные отчёты `wizard-check-materials.py` по каждому шагу (JSON: статус, найденные файлы, предупреждения)
- Финальный summary: что готово, что пропущено, что сгенерит AI

## Внутренний поток

1. **Pre-flight** — проверяет что `codex` установлен (вызывает `install-codex.sh` если нет)
2. **Приветствие** — 3 коротких абзаца о системе, без воды
3. **Slug** — спрашивает имя проекта, валидирует kebab-case
4. **Создание папки** — вызывает [[landing-project-init]] skill
5. **4 шага материалов** — для каждого: заголовок → путь → что класть → «готово»/«пропустить» → проверка через [[wizard-check-materials]]
6. **Финиш** — summary + подсказка `/landing-go` (не запускает сам, даёт паузу)

Шаг 1 (прототип) **hard-required**: пропустить нельзя. Шаги 2–4 optional — wizard принимает «пропустить» и помечает слот для AI-fallback.
